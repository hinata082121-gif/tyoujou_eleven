## 1. コンセプト

- プレイヤーは高校サッカー部の監督。弱小校を育て、全国の頂点を目指す。
- 中心となる遊び：
  - すごろく式のカレンダー進行（育成・イベント）
  - 3年で部員が入れ替わるサイクル
  - 学校評判が上がるにつれて手札・新入生・スカウト・スタッフ枠が広がる成長ループ
  - 能力に基づく試合シミュレーションと采配
- ゲームに終わりはなく、年度を重ねて学校の歴史が積み上がる。
- 仮タイトルは「**頂上イレブン**」。表示名は `src/engine/config/names.ts` に置き、差し替え可能にする。

## 2. 公開・技術方針

- **収益化**：初期は広告・課金なし。Vercel（Hobby）で無料公開する。人気が出たらアプリ化し、広告・課金を入れる予定。
- **アプリ化への備え**
  - Next.js（App Router）＋TypeScriptで作り、`output: 'export'` による**静的書き出しのみ**で動くこと。API Routes・SSR・Server Actionsは使わない。
  - 将来Capacitor等でアプリ化しやすいよう、ブラウザ標準APIだけで動作させる。
- **デザイン**：**横画面**で遊ぶ（スマホは横向きに固定する前提。将来アプリ化するときも横画面）。縦に持ったときは「端末を横向きにしてください」の画面を出す。ノッチ・ホームバー（セーフエリア）に操作や文字を重ねない。縦に積むより、左右に情報を並べる配置にする。PC・タブレットでも横長で表示する（PR1 で決定。`docs/PHASE_R1_PLAN.md`）。
  - 見た目のルール（色・フォント・余白・枠・影などの基本値）は `docs/DESIGN.md` に従う。角は丸めない（使っても 2px まで）。絵文字は使わず、ゲーム用に描いた SVG のアイコンを使う。フォントは自分のサイトから配信する。
- **ゲームロジック**：`src/engine/` に**UIから独立した純粋なTypeScript**として実装する。React・DOMには依存しない。
- **乱数**：シード指定できる疑似乱数（PRNG）を使う。乱数の状態はセーブデータに含める。
- **状態管理**：Zustand。
- **テスト**：Vitest。エンジンには単体テストと、大量の試合をシミュレーションするバランステストを必ず用意する。
- **デプロイ**：GitHub → Vercelの自動デプロイ。
- **アクセス解析**：将来の判断材料として、後のフェーズで入れる（Phase 5）。

## 3. 知財・名称ルール（厳守）

- 「パワプロ」「栄冠ナイン」などの名称、それらに固有の用語、キャラクター、UIの見た目を使わない。
  - 避ける用語の例：「進行アイコン」「戦術レベル」「伝令」「転生選手」
- 実在の高校名・選手名・Jクラブ名・大会の正式名称・商標を使わない。
  - 「インターハイ」は商標なので使わない。
- **都道府県名・地域名は実在の名前を使ってよい。** 学校名・選手名・大会の正式名称・商標は、引き続き架空または一般的な名前にする。
  - 実在の高校のデータ（強さ・校数など）は使わない。県ごとの傾向は架空のものにする。
- 大会名などの表示名はすべて `src/engine/config/names.ts` に集約し、後から差し替えられるようにする。
  - 大会の表示名は「**冬の全国大会**」（高校選手権に相当）と「**夏の全国大会**」（インターハイに相当）。
- キャラクターは**独自デザインの2〜3頭身デフォルメ**にする。既存ゲームのキャラクター特有の造形は真似しない。
  - P4：腕と脚は胴体とつながった形にするなど、独自の体型にする。
- **ユニフォーム・スタジアム（P4）**：すべて独自のデザインにする。実在のクラブ・ブランドのユニフォームのデザインやロゴは真似しない。
- **3D素材（P4）**：外部から持ち込まず、コードで作る（球・円柱・箱などの基本形状の組み合わせと、Canvas などコードで描いたテクスチャ）。

## 5. すごろく式の進行

- **手札**：評判に応じた枚数の「進行カード」を持つ（6章の表を参照）。カード1枚につき、数字1〜5と種類を持つ。
- **カードの使い方**
  - カードを1枚使うと、その数字の日数だけカレンダーを進む。
  - 使ったカードは補充される（種類と数字はランダム。評判や設備で出やすさが変わる）。
- **1マス＝1日**。1年は4月1日から3月31日までのマスで構成する。
- **カードの種類＝練習の種類**（練習カードの表のうち、そのフェーズで使えるもの。休養を含む）。カードを使うと、その練習を進んだ日数だけ行う。
- **イベントは止まったマスだけ**で発生する。通過したマスでは発生しない。
- **テンポ**：カードを使う操作は1タップで済ませる。移動の演出はスキップできるようにする。
- **経験点**：経験点 ＝ 練習1日あたりの値 × 実際に進んだ日数。
- **必ず止まるマス**：試合・試験・行事などのマスは必ず止まる。その手前で大きな数字のカードを使っても、そのマスで止まる（効果も止まった日数分だけ）。
- **マスの種類**

| マス | 効果 | 実装フェーズ |
|---|---|---|
| 青 | 良いイベント | P1 |
| 赤 | 悪いイベント | P1 |
| 白 | 良いか悪いかランダム | P1 |
| 緑 | 体力回復 | P1 |
| 黄 | 直前の練習の効率アップ | P1 |
| 大マス | 必ず止まる（試合・試験・行事など） | P1 |
| 特訓（紫） | 止まると、そこまで使った練習カードの対象者全員が、その練習に応じた特殊能力の習得を判定する（7.7） | P2b |
| 分岐（☆） | 止まると道が2〜3本に分かれ、選べる（5.1） | P2c |
| 人物マス | OB・マネージャーなどのイベント | P2c 以降 |

- **練習カード（仮）**：チーム練習として、対象の部員全員に経験点が入る。

| カード | 主に伸びる能力 | 対象 |
|---|---|---|
| シュート練習 | シュート、キック力 | フィールド選手 |
| パス練習 | パス、視野の広さ | 全員 |
| ドリブル練習 | ドリブル、テクニック | フィールド選手 |
| 守備練習 | 守備、判断 | フィールド選手 |
| フィジカル | フィジカル、空中戦 | 全員（空中戦はフィールド選手のみ） |
| 走り込み | スピード、スタミナ | 全員 |
| 戦術ミーティング | 判断、視野の広さ | 全員（判断はフィールド選手のみ） |
| GK練習 | セービング、ハイボール、ポジショニング、キャッチング | GKのみ |
| セットプレー | キック力、空中戦 | フィールド選手 |
| PK練習 | PK駆け引き | 全員（P2a） |
| 休養 | 体力を大きく回復 | 全員 |

- **分岐マス（5.1。P2c）**
  - 止まると道が2〜3本に分かれ、プレイヤーが選べる。通過したとき（止まらなかったとき）は「ふつうの道」を進む（P2c で決定。計画 Q13）。
  - それぞれの道で、マスの並び（青マスが多い、特訓マスがある、休養が多い、など）が違う。
  - 選ぶ時点で、先のマスの並びがある程度見える。
- **イベント**：P1では10〜15種類の最小限にする（例：差し入れで体力回復、雨で練習中止、ケガ、やる気アップ）。【未決】詳細は後のフェーズで追加する。

  - 評判（5段階）は、手札・新入生・スカウトなどを決める学校の格。
  - ランク（E〜S）は、その年のチーム力から計算する強さの目安。自校にも表示する。
  - 目安：弱小≈E、そこそこ≈D、中堅≈C、強豪≈B、名門≈A。**Sは飛び抜けたチームだけ**。

### 7.3 能力どうしの組み合わせ（試合判定で必ず再現すること）

- **視野の広さ × 判断**：見えていても、強い相手には出せない
  1. 視野の広さで、パスの出しどころ（候補）の数が決まる。
  2. 判断で、パスを出すまでの速さが決まる。
  3. 相手の守備の質（守備・判断・プレスの強さ）によって、パスを出せる時間の余裕が短くなる。
  4. 判断の速さがその余裕に間に合わなければ、そのパスは出せない。
  - 結果として、弱い相手には出せるパスが、強い相手には出せなくなる。
- **判断（攻撃時）**：ボールを持っていないときの動き出しの質に効く。良い位置で受けられるかどうかが決まり、チャンスの質が上がる。
- **キック力の組み合わせ**
  - ロングパス＝パス（精度）×キック力（届く距離）。キック力が足りないと、精度が高くても届かずに奪われる。
  - シュート＝シュート（精度）×キック力（強さ）。ミドルシュートはキック力の比重が大きい。
- **GKの判定の流れ**
  1. ポジショニングで「止めにいける範囲」が決まる。
  2. その範囲の中で、セービングで止められるかが決まる。ポジショニングが低いと、セービングが高くても届かないコースが増える。
  3. セーブした後、キャッチングが高ければボールを確保して終わる。低いとこぼれ球になり、相手に2本目のシュートの機会が生まれる。
  4. クロスへの対応は、ハイボールでボールに届くかが決まり、キャッチングで確保できるかが決まる。キャッチングが低いとファンブルが起きる。
- **ビルドアップの戦術とGK**
  - 戦術を「ビルドアップ重視」にすると、GKのパスとテクニックが効く。この2つが低いと、自陣ゴール前でボールを奪われるイベントが起きる。
  - 戦術を「ロングボール主体」にすると、GKのキック力が効く。

### 7.4 成長

- 練習カードの経験点を、該当する能力に振り分ける。
- 能力値が高いほど、次の1ポイントを上げるのに多くの経験点が必要になる（インフレ防止）。
- 選手ごとに隠しパラメーター「伸びしろ」を持たせ、成長量に補正をかける。
- 調整用の数値はすべて `src/engine/config/` に集約する。

### 7.5 性格（P2b）

- 選手は全員、性格を1つ持つ（CPU 校の選手も持つ）。
- P2a の仮の隠しパラメーター「指導の素質」は性格に置き換え、スタッフの指導力の決まり方に使う（9章）。

| 性格 | 練習の得意 | 試合でのメンタル | キャプテンにしたとき | 指導の素質 | 伸ばしやすいスタイル |
|---|---|---|---|---|---|
| 努力家 | 全般に安定して伸びる | 調子の波が小さい | チーム全体の練習効率が少し上がる | 高 | どれでも平均的 |
| 情熱家 | フィジカル・走り込み | 終盤に強い。熱くなってカードをもらいやすい | ビハインド時にチームの士気が上がる | 中 | ボックストゥボックス、ボールハンター、ストッパー |
| 冷静沈着 | 戦術ミーティング・パス | PKに強い。調子の波が小さい | 終盤の判断ミスが減る | 高（戦術眼） | No.10、リンクマン、カバーリング、ビルドアップ型 |
| 職人気質 | 得意な練習1つが大きく伸び、ほかは普通 | セットプレーに強い | 効果は小さい | 専門分野に強い | ポーチャー、クロッサー、砲台、ボックスキーパー |
| 負けず嫌い | 試合で得る経験点が多い | 格上相手に強い。負けると調子が落ちる | 格上との試合でチームの士気が上がる | 中 | ストライカー、インサイドドリブラー、ボールハンター |
| ムードメーカー | 普通 | 調子の波が大きいが、上がりやすい | チーム全体の調子が安定し、上がりやすくなる | 低〜中 | スピードスター、ウイングドリブラー、攻撃的サイドバック |
| 慎重派 | 守備系が得意、シュート系が苦手 | ミスが少ない。大舞台では少し萎縮する | 失点した後に崩れにくい | 中（分析） | アンカー、カバーリング、空中戦の番人 |
| ひらめき型（まれ） | 伸びは大きいが、当たり外れも大きい | 波が大きく、ここ一番で特殊能力が発動しやすい | 効果は小さい | 低（名選手、名監督にあらず） | ウイングドリブラー、インサイドドリブラー、No.10 |

- ひらめき型は新入生の数%程度にする。
- 効果量の初期案は `docs/PHASE2B_PLAN.md`。数値は `src/engine/config/` に置く。
- **試合経験点（P2b で決定）**：出場した選手には、出場時間に応じて、ポジションに合う能力に少し経験点が入る。負けず嫌いは1.5倍。総合B以上の割合（14章）が変わらないよう、練習の倍率で戻す。
- **大舞台（P2b で決定）**：全国大会の試合と、県予選の決勝。性格（慎重派）と特殊能力（大舞台系）で使う。

### 7.6 プレースタイル（P2b）

- 1人1つだけ持つ。サブのスタイルは持てない。
- **プレースタイル熟練度**を持つ。試合と練習で上がり、上がり方は性格で変わる（7.5の「伸ばしやすいスタイル」）。
- 熟練度が高いほど、次の2つの効果が強くなる。
  - 試合で、そのスタイルらしいプレーが起きやすくなる
  - スタイルに合った能力が伸びやすくなる
- **スタイルは変更できる。** 変更すると熟練度は0から始まり、すぐには力を発揮できない。
- **新入生と既存の選手のスタイル**は、ポジションと能力の傾向から決める。
- **選べる範囲（P2b で決定）**：主ポジションか、適性◎○のポジションの区分（FW＝CF・WG、MF＝DMF・CMF・OMF・WG、DF＝CB・SB、GK）に入るスタイル。区分の外の枠で使うと、スタイルの効果も動きの範囲も出ない（「自由」として扱う）。変更は試合中以外ならいつでもできる。

「FW/MF」「MF/DF」は、どちらのポジションで使っても効果を発揮するという意味。

**効果量の目安**
- ○＜◎＜金色の順に効果を強くする。
- 金色の特殊能力は、持っている選手がいるとはっきり分かる強さにする。ただし、1人で試合をひっくり返すほどにはしない。

**入手方法**

- **マイナスの特殊能力**：特訓やスタッフのイベントで消せる。
- **新入生**：数%の確率で特殊能力を最初から持つ（主に○と×）。

**P2b で決めたこと**
- **特訓マス**：新しいマスの種類（紫）。通常マスの約7%。止まると、そこまで使ったカードの練習の対象者全員が、その練習に応じた候補で習得を判定する。休養カードのときは×を消す判定だけ。
- **試合での成果の「1大会でハットトリック」**は、公式戦の1試合で3得点とする。
- **両利き**：最高難易度のレジェンドスキル。新入生が最初から持つことはない（0%）。習得の条件は「逆足×がない、熟練度80以上、シュートかドリブルの特訓で1%」だけ。
  - 利き足の「両足」はなくし、利き足は右か左だけにする。P2a までのセーブの「両足」の選手は、マイグレーションで右足か左足に振り分ける（逆足×は付けない）。
  - 目安：両利きを持って卒業する選手はごくまれ（1%未満）。
- **金色の成果の条件**：公式戦だけで数える（練習試合は含めない）。今の回数（1〜4回）は P2b の間の仮の値。P2c で公式戦が増えたら回数を上げ直し、金色の種類ごとの難しさをそろえる（卒業生の金色の内訳が、特定の種類に集中しないことを目安にする）。金色を持って卒業する割合は 2〜5% を維持する（P2c）。
- **金色の存在感**：金色を持つ選手は、その金色に関係するプレーでだけ実効能力が少し上がる（場面の効果に加えて）。対人の鬼・空中戦の要は守備、1対1職人・ボンバーヘッドはシュート、クロスの名手・CKの名手はパスとクロス、1対1の壁・フィードの名手はGKのプレー、FKの名手・PK職人はセットプレー（直接FK・PK）、両利きはシュートとドリブル。目安は金色1人の効果が平均+2pt前後。
- **キャプテンシー**：キャプテンのとき、チーム全体の実効能力が ○ 1.01倍・◎ 1.015倍。
- **CPU 校の選手**も性格・スタイル・熟練度・特殊能力を持つ。習得は年2回（年度替わりと秋の成長）の簡略な判定。
- **色分け**：○ 緑、◎ 青、金色 金、× 灰色（既存ゲームの配色と分ける）。
- **P2a のセーブを読み込んだとき**：既存の選手の熟練度と特殊能力は学年に応じて付ける（3年生で熟練度50〜75、プラスの特殊能力が平均1個前後。金色は付けない）。
- 効果量・習得確率・条件の初期案は `docs/PHASE2B_PLAN.md` の4〜5章。数値は `src/engine/config/` に置く。

**画面**
- 選手の詳細画面に、性格、プレースタイルと熟練度、特殊能力を表示する。特殊能力は○・◎・金色・×で色分けする。
- 特殊能力の一覧と説明を見られる画面（図鑑）を作る。
- 部員一覧で、スタイルと特殊能力で絞り込みや並べ替えができる。

### 7.8 キャプテン（P2b）

- 年度初めに、部員から1人をキャプテンに指名する。
- キャプテンの性格の効果（7.5）と、特殊能力「キャプテンシー」の効果がチームに乗る。
- キャプテンが試合に出ていないときは、効果を弱める。
- CPU 校も自動でキャプテンを決める。
- **指名の時期（P2b で決定）**：年度初め（スタッフの編成の後）と、3年生の引退でキャプテンがいなくなったとき。全学年から選べる。それ以外の時期には変えられない。
- 試合に出ていないときは、試合中の効果を半分にする（練習・調子への効果はそのまま）。
- キャプテンシーを持っていても、キャプテンでなければ効果はない。

## 8. 部員・新入生・特待生スカウト

- **地域区分**（スカウト範囲の「所属地域」「隣接地域」に使う）：北海道／東北／関東／北信越／東海／近畿／中国／四国／九州。

- **部員数**：1学年の人数は評判で決まる（6章の表）。部全体ではおよそ27〜42人。
- **新入生**：4月に入部する。人数は、評判で決まる1学年の人数から、入部が決まった特待生の数を引いた分を一般入部で生成する。
- **特待生スカウト（P2c）**
  - 期間は11月〜2月。すごろくにスカウトカードが出る。カードの枚数・スカウト範囲・特待生枠は評判で決まる（6章の表）。
  - **スカウト範囲**：自県 → 所属地域 → 地域＋隣接地域 → 全国 と広がる。地域の隣接関係は実在の9地域をもとに設定データで持つ（案は `docs/PHASE2C_PLAN.md` 3章）。
  - **候補の中学生**
    - 所属は「中学の部活」「街クラブ」「ジュニアユース（架空）」の3種類。
    - 都道府県・地域ごとに傾向がある（攻撃型が多い、GKが多い、など。架空の傾向）。
  - **能力の水準**：特待生の候補は、CPUの強豪校の新入生と同じ水準にする。ただし、取り合いになる最上位の候補は、その一段上にする。
    - **P3 で変更（2026-10-13。計画 Q7）**：自校の評判が強豪のときは候補の水準を一段上げる（ふつうの候補は格4、最上位の候補は格5の新入生の水準）。名門のときは二段上げる（ふつうの候補は格5、最上位はその上）。名門の自校が A に届き、全国優勝を狙えるようにするため。人数は変えない。名門のときは、さらに候補の基準値を 1.5 上げる（2026-10-13。報告書 4章 Q1・Q3 の調整で一般入部の成長を少し抑えたため）。
  - **能力表示**：候補リストの能力メーターは正確ではない。中学時代の実績が高い選手ほど表示が正確になる。分析担当スタッフのスカウティング能力が高いほど、メーターと寸評も正確になる。
  - **寸評**：性格、プレースタイルの素質、特殊能力の素質、伸びしろを文章でほのめかす。
  - **反応**：反応は「良好・普通・悪い」の3段階。
    - 能力の高い選手ほど反応が悪くなりやすく、評判が低いと好転しにくい。
    - 再訪問すると反応が好転することがある。
    - 寮のレベル（15章）が高いと、反応が良くなりやすい。
    - 反応が良好でも、入部は確定ではない。
  - **取り合い**：有望な選手ほど、ジュニアユースから上がるユースチーム（架空）や、他の強豪校との取り合いになる。
  - **入部**：入部が決まった特待生は、翌年4月に入部し、評判で決まる1学年の人数の一部になる（不足分は一般入部で埋める）。人数は評判で決まる特待生枠（2〜5人）が上限。
  - **CPU校**：CPU校の特待生の獲得は、簡略化したモデルでよい。
  - **P2c で決めたこと（2026-10-11。計画 Q8〜Q10）**
    - スカウトカード1枚＝候補1人の訪問。使うと1日進む（その日は練習しない）。カードは11月〜2月に均等に届き、2月28日で消える。
    - 訪問した候補は自動で「勧誘中」になり、2月28日に一斉に返事が届く。特待生枠を超えて入部が決まったら、勧誘画面で付けた優先順で枠まで。
    - 取り合いに負けた候補：ユースへ行った候補は消える。他校へ行った候補は、その学校の新入生として入部する。
    - 数値の初期案は `docs/PHASE2C_PLAN.md` 3章。
- **卒業**：卒業した部員はOBとして記録する。進路（プロ、大学、社会人、指導者の道など）を持たせる。OBの記録はスタッフ制度で使う。

## 9. スタッフ（コーチ）制度（P2a）

- **候補**：スタッフは卒業生（OB）の中から選ぶ。
- **ゲーム開始時**：卒業生がいないため、学校を作るときに架空のOBを数人自動で生成しておく。
- **枠**：評判で決まる（6章の表。名門で最大3人）。
  - **ヘッドコーチは必須**。
  - 残りの枠には、GKコーチ・フィジカルコーチ・分析担当の中から配置する。
- **役割とパラメーター**

| 役割 | 主なパラメーター | 効果 |
|---|---|---|
| ヘッドコーチ（必須） | 指導力、戦術眼 | 練習効率アップ。結果のみモードでの采配の質 |
| GKコーチ | GK指導 | GKの練習効率。PK駆け引きの伸び |
| フィジカルコーチ | 体力管理 | 疲労回復（連戦の疲れの抜けやすさを含む。10.3）、ケガの予防 |
| 分析担当 | スカウティング | PKの読み、相手の傾向を表示、特待生スカウトの精度 |

- **能力の決まり方**
  - **現役時代の能力**で得意分野が決まる。例：GKだった人はGK指導、判断が高かった人やキャプテン経験者は戦術眼。
  - **卒業後の進路**で伸び方と、スタッフになれる時期が決まる。例：大学に進んだ人は4年後から雇える。プロに進んだ人は引退後に戻ってくる。
  - **「名選手、名監督にあらず」**：指導力は現役時代の強さより、性格や進路で決まる割合を大きくする。
  - P2a の仮の隠しパラメーター「指導の素質」は、P2b で性格（7.5）に置き換える。
- **成長**
  - 在任中に成長する。成長のきっかけは、在任年数、担当分野の成果、大会成績。
  - **得意分野1〜2個**だけ、上限が100（SS）まで届く可能性がある。それ以外の能力の上限は60〜80程度。
  - 上限の数値は表示しない。寸評でにおわせる。
  - 上限に近づくほど伸びにくくなる。年齢が上がると伸びが止まり、最後は勇退する。
- **インフレ防止**
  - 練習効率の補正は最大でも+15%程度にする（P2c からは設備（15章）の補正と合わせて上限を設ける）。
  - 年齢・在任年数で勇退させる。
  - 優秀なスタッフほど、他校やプロに引き抜かれる確率が上がる。
  - 相手校もスタッフ能力を持つ（簡略化した値でよい）。
- **ヘッドコーチがいなくなった場合**：候補がいなければ、能力の低い「臨時コーチ」を自動で配置する。
- **雇用と配置換えの時期（P2a で決定）**
  - 原則は年度初め（4月）。欠員（解任・引き抜き・勇退・年度途中に評判が上がって増えた枠）は年度の途中でもすぐ補充できる。
  - 解任はいつでもできる。解任した人は、その年度は雇い直せない。
  - 評判が下がって枠が減ったときは、次の年度初めに誰を残すかを選ぶ。
- **主将（P2a）**：毎年4月に3年生から自動で決める（総合と判断が最も高い選手）。OB の記録に残し、戦術眼の素地に使う。P2b からはキャプテン制度（7.8）で監督が指名する。
- **年齢と勇退（P2a）**：卒業時を18歳とし、年度ごとに1つ上がる。60歳から毎年20%の確率で勇退し、68歳で必ず勇退する。
- **引き抜き（P2a）**：12月に予告し、年度末に70%の確率で去る。引き留める手段は P2a では作らない。
- 式と数値の初期案は `docs/PHASE2A_PLAN.md` の2〜4章。数値は `src/engine/config/staff.ts` に置く。

## 10. 試合

### 10.1 基本の仕組み

- **結果は確率で決める**：試合エンジンは、確率をもとに「何分に、誰が、何をしたか」というイベントの並びを生成する。物理演算による本格的なシミュレーションはしない。
- **表示は再生するだけ**：テキスト・2D・3Dの各表示は、エンジンが生成したイベントから組み立てた「演出タイムライン」を再生するだけ。表示が試合結果に影響してはならない。
- **区間ごとに計算する**：1区間＝5分として、区間ごとに計算を進める（一度に試合全体を計算しない）。采配を変えると、次の区間から反映される。

### 10.2 試合のルール（大会ごとに設定データで持つ）

| 大会 | 試合時間 | 引き分けの場合 |
|---|---|---|
| 冬の全国大会（準々決勝まで） | 80分 | 延長なしですぐPK戦 |
| 冬の全国大会（準決勝） | 90分 | 延長なしですぐPK戦 |
| 冬の全国大会（決勝） | 90分 | 20分の延長、それでも同点ならPK戦 |
| 夏の全国大会（県予選・本戦） | 70分（交代5人） | 決勝のみ10分ハーフの延長。それ以外はすぐPK戦 |
| 新人戦（県大会・地域大会） | 70分（交代5人） | 決勝のみ10分ハーフの延長。それ以外はすぐPK戦 |
| リーグ戦 | 80分（交代5人。P3 で決定） | 引き分けで終了 |
| 練習試合 | 大会設定に従う | 引き分けで終了 |

- **登録**：試合にエントリーできるのは20人（先発11人＋控え9人）。
- **交代**：最大5人。大会ごとに「交代回数は3回まで」の制限を設定できるようにする。
- 延長戦での追加交代は【未決】。P1ではなしでよい。
- **冬の全国大会の県予選**は、全国大会と同じ試合ルール（上の表）で行う。
- 「交代回数は3回まで」の制限はフラグとしてデータに持つが、P1では使わない。
- **試合中のカード（警告・退場）とケガ**（P2a）
  - 守備の判定のときに確率でファウルが起きる。ボックス内なら PK、ボックス外ならフリーキック。
  - ファウルからイエローカード、まれに一発レッド。2枚目のイエローで退場。退場した選手は次の公式戦1試合に出場停止（イエローの累積による出場停止はなし）。
  - 退場者が出たら10人用のフォーメーションは使わず、空いた枠のまま人数差の補正をかける。GK が退場したら、控えのGKと交代枠があれば自動で交代する。
  - ケガをした選手はピッチを離れ、通常の交代枠で交代する（観戦中は一時停止して選ぶ。選ばずに再開したら、その位置に最も合う控えが入る）。交代枠がなければ人数が減ったまま戦う。重さに応じて試合後に離脱日数を付ける。
  - CPU 校の選手のケガ・退場はその試合の中だけ反映し、持ち越さない。
  - 目安：イエローは両チーム合計で1試合2〜3枚、レッドは数十試合に1枚。
- **試合中のPK**（ペナルティエリア内のファウル）は、P2a からファウルの流れの中で起きる。判定は10.6と同じ。

### 10.3 判定モデル（初期案。数値は調整前提）

1. **ゾーン別の評価値**：選手の能力×ポジション適性×フォーメーション補正から、ゾーンごとの評価値を計算する（攻撃は左・中央・右、中盤、守備は左・中央・右、GK）。
2. **ボール支配**：区間ごとに、両チームの中盤の評価値の比率に戦術補正をかけて支配率を決め、攻撃の回数を確率で配分する。
3. **攻撃1回ごとの判定**
   1. 攻撃ルートを選ぶ（中央／サイド／カウンター／ロングボール／セットプレー）。
   2. 7.3節の「視野の広さ×判断」でチャンスになるかを判定する。
   3. シュートの質を「シュート×キック力」と相手の守備で判定する。
   4. 7.3節のGKの判定の流れで結果を決める（こぼれ球なら2本目のシュートへ）。
4. **疲労**：スタミナとプレスの強度に応じて、区間ごとに体力が減る。体力が下がると能力に補正がかかる。補正は体力80%を切ると始まり、70%前後からはっきり大きくなる（70%で約1割、60%で約3割、50%以下で4割5分の低下）（終盤に元気な選手を入れる意味があるように。2026-10-09）。
   - **連戦の疲労（P2c）**：全国大会（夏・冬）などの連戦では、前の試合の疲労が次の試合に残る。主力を休ませるターンオーバーが戦略として意味を持つ程度にする。疲労の抜けやすさは、フィジカルコーチの体力管理と、設備（ケアルーム・寮）で変わる。両方が最高でも、連戦の疲れが完全には抜けない上限を設ける。数値の案は `docs/PHASE2C_PLAN.md` 8章。
5. **得点の分布**：変換関数（シグモイド等）で、極端な結果にならないよう調整する。

### 10.4 試合モードと采配

| 試合の種類 | 選べるモード | 采配のタイミング | 表示 |
|---|---|---|---|
| トーナメント（公式の大会） | 観戦のみ（結果のみは選べない） | 試合前・ハーフタイム・観戦中いつでも（一時停止して交代や戦術変更） | 3D（P4。試合の全時間。設定で「2D＋速報」「テキストのみ」も選べる。10.8） |
| リーグ戦 | 「采配あり」と「結果のみ」を進行中いつでも切り替え可 | 采配ありは試合前とハーフタイムのみ | 采配ありは簡易2D（P3） |
| 練習試合 | リーグ戦と同じ（P1から、試合前に「観戦する／結果のみ」を選べる） | リーグ戦と同じ | リーグ戦と同じ |

- **采配で操作できること**：スタメン、フォーメーション、戦術、交代。
- **フォーメーション（P1）**：4-4-2、4-3-3、4-2-3-1、3-5-2、5-3-2。
- **試合前に見える相手の情報**：基本フォーメーションと攻撃方針だけ。プレス・ラインなどの細かい傾向は、P2aから分析担当がいる場合だけ表示する（P2a では正確に表示する。能力で正確さを変えるのは P2b）。
- **ハーフタイムに見える情報**：前半の支配率、シュート数（枠内）、ゾーン別（左サイド・中央・右サイド）の攻撃回数と好機の数、どこで押されているか。
- **戦術**

| 項目 | 選択肢 |
|---|---|
| 攻撃方針 | 攻撃的／バランス／守備的 |
| 組み立て | ビルドアップ重視／ロングボール主体 |
| プレス | 高／中／低 |
| ライン | 高／低 |

- **戦術の相性（循環型）**：どの戦術にも苦手な相手がいるようにし、どんな場面でも一番強い戦術は作らない。
  - ハイプレス → つなぐ（ビルドアップ）に強い。ロングボール → ハイプレス（前がかり）に強い。引いて守る（ライン低）→ ロングボールに強い。つなぐ → 引いて守る相手に強い。
  - ロングボール主体でライン高にすると、全体を押し上げるぶんロングボールが前線に届きやすくなる（代わりに裏を取られやすい）。パワープレイの効き目はここから出る。
    - **P3 で変更（2026-10-13）**：この「届きやすさ」は、ビハインドかつ残り15分以内（パワープレイの場面）だけ効く。ふつうの時間帯のロングボール主体・ライン高の型が強くなりすぎていたため。
  - プレス高は体力の消耗が大きい（プレス中の1.25倍。P3 で 1.4倍から変更。ハイプレスの型が後半に失速して弱すぎたため）。
  - 目標：4つの型の平均の勝ち点（同じ強さ、勝ち3・分け1）がすべて1.35〜1.45に入る。
  - **堅守速攻は格上に番狂わせを狙う型**：守備的・ライン低で格上と戦うときは、相手とのランク差が大きいほど守備とカウンターが強くなる（最大3段階分）。同じランクどうしの相性には影響しない。
  - CPU校は「ポゼッション／ハイプレス／ロングボール／堅守速攻」の4つの型のどれかで戦う。型に合うフォーメーションを使うので、見えている情報（基本フォーメーションと攻撃方針）から型を読める。
- **采配ありを有利にする**：結果のみモードでは、AIの監督が采配する。采配の質はヘッドコーチの戦術眼で決まり、作戦ノートがあればそれも使う。自分で采配した方が有利になるよう調整する。
- **計算は共通**：采配ありでも結果のみでも、同じ試合エンジンで計算する（計算式を分けない）。
- **P3 で決めたこと（2026-10-13。計画 Q4・Q5）**
  - 采配あり／結果のみは試合前の画面で選ぶ。初期値は設定（「リーグ戦の試合」）で、いつでも変えられる。
  - 采配ありで観戦している途中に「結果のみに切り替える」ことができる（残りは AI の監督が采配する）。逆はできない。
  - 采配ありの観戦中、ケガ人が出たときは作戦ノートか AI の監督が自動で交代させる（采配できるのは試合前とハーフタイムだけのため）。
  - 簡易2D は、リーグ戦・練習試合の采配ありに加えて、トーナメントの観戦でも選べる（テキスト表示と切り替え）。**P4 で3D観戦ができた後も、トーナメントで2Dを選べる設定は残す**（動作の重いスマホ向け）。
  - 2D は、エンジンのイベントから作る「演出タイムライン」（`src/engine/replay/`）を再生するだけ。P4 の3Dも同じタイムラインを使う。キャラクターは丸と背番号だけ（独自デザインのキャラは P4）。

### 10.5 作戦ノート（条件付きルール。P2a）

- **条件**（いくつでも組み合わせられる）
  - 時間：○分以降、残り○分
  - スコア：○点リード、同点、○点ビハインド
  - 選手の状態：スタミナ○%未満、イエローカード、ケガ
  - その他：交代枠が残っているか、大会の種類
- **行動**
  - 選手交代（A→B）
  - フォーメーション変更
  - 戦術変更
  - ポジション変更
- **優先順位**：ルールに優先順位を付ける。交代枠が足りないときは、優先順位の高いルールから実行する。
- **数の上限**：1つのノートにつき8ルールまで。
- **手動操作が優先**：観戦中に自分で交代したら、関係するルールは止まる。
- **結果のみモード**でも作戦ノートを使う。
- **テンプレート**

| テンプレート | 条件 | 行動 |
|---|---|---|
| パワープレイ | ビハインドで残り10分 | 長身FWを投入し、ロングボール主体・攻撃的・プレス高・ライン高に |
| 逃げ切り | 1点リードで残り10分 | 疲れた選手を代え、守備的・ライン低に |
| 疲労交代 | 選手Bのスタミナが70%未満（ノートで変えられる） | 選手Cと交代 |
| PK準備 | トーナメントで同点、残り3分 | PK専門GKを投入 |

- **判定の決まり（P2a で決定）**
  - 区間の終わりに判定し、次の区間の頭で反映する。
  - 「残り○分」は、今のスコアのままなら試合が終わる（または PK 戦に入る）までの時間。延長がある試合で同点なら、延長の終わりまでを数える。
  - 1つのルールは1試合1回だけ発動する。行動を全部実行できるときだけ発動し、できなければ下のルールに進む。
  - ノートは3冊まで保存でき、試合前の画面で使うノートを選ぶ。
  - 疲労交代の初期値は70%（2026-10-09 に 60% から変更）。体力が70%前後を切ると能力の低下がはっきり出る（10.3 の 4）。
  - 逃げ切りは当初「5バックに」だったが、並び替えで適性の低い位置に入る選手が出て逆効果だったため、守備的・ライン低に変えた（2026-10-09）。
- **采配の代償（2026-10-09）**：攻撃的にすると得点の機会が増える代わりに、カウンターで失点しやすくなる。守備的にすると失点しにくくなる代わりに、得点の機会も減る。
- **結果のみモードの AI**：ノートが決めていない部分は、ヘッドコーチの戦術眼に応じた質で AI が采配する。戦術眼が最高でも、自分でうまく采配した場合と同じくらいまでにとどめる。

### 10.6 PK

- **プレイヤーが決められるのはキッカーの順番だけ**。コースの選択はできない。
- **1本ごとの判定**
  - キッカー側の読み＝キッカーのPK駆け引き＋キッカー側チームの分析担当のスカウティング
  - GK側の読み＝GKのPK駆け引き＋GK側チームの分析担当のスカウティング
  - 相手校も分析担当の能力を持つ。
  - キッカーがGKの逆を突いた場合：ほぼ得点になる。ただし、キック精度が低いと枠を外すことがある。
  - GKが読みを当てた場合：「シュート＋キック力」と「セービング＋ポジショニング」を比べて結果を決める。
- **ルール**：5本ずつ蹴り、決着しなければサドンデス。PK戦に参加できるのは、試合終了時にピッチにいた選手のみ（だからPK専門GKは試合終盤に投入する）。
- 試合中のPKも同じ判定を使う。
- 分析担当がいないチームは、スカウティングの項を0として扱う。CPU 校は簡略化したスタッフの値を使う。

### 10.7 観戦の時間

- **等速**：試合時間15分＝現実の1分。80分の試合で約5分20秒、ハーフタイムとPK戦を含めて1試合6〜8分が目安。
- **倍速**：2倍と4倍を選べる。
- **テキスト表示（P1）**：テキスト速報、スコアボード、試合の流れ（モメンタム）の表示。
- **試合中のセーブ**：区間（5分）ごとに試合の状態と乱数の状態をセーブし、リロードしたらその区間から再開する（やり直しで結果を変えられない）。

### 10.8 3D観戦（P4）

- **結果は今までどおりエンジンが決める**。3Dは、エンジンのイベントから作った演出タイムライン（`src/engine/replay/`）を再生するだけ。3D・2D・テキストのどれで見ても結果は同じ（10.1）。
  - 試合エンジン（`src/engine/match/`）の判定は変えない。演出に必要な情報が足りなければ、P3 の `lane`・`zone` と同じく、乱数の使い方を変えない形で記録だけを足す（結果が変わらないことをテストで確かめる）。
- **どの試合を3Dで見るか**

| 試合 | 表示 |
|---|---|
| トーナメント（公式の大会）の観戦 | 試合の全時間を3Dで再生（標準） |
| リーグ戦・練習試合の「采配あり」 | 今までどおり簡易2D（P3） |

- **観戦の表示の設定**：トーナメントは「3D／2D＋速報／テキストのみ」から選べる。標準は3D。2Dを選べる設定は、動作の重いスマホ向けに残す（P3 で決定）。
- **自動で2Dに切り替える**：端末が WebGL に対応していない、または3Dの読み込みに失敗したとき。
- **3D観戦中も使える機能**：一時停止していつでも采配（トーナメントはいつでも采配できる）、等速（試合時間15分＝現実の1分）・2倍・4倍、テキスト速報（画面の下に直近の数行を重ねる）、スコアボードと試合時間、ハーフタイムと PK 戦の画面、特殊能力が発動したときの速報（P2b）。
- **技術**：Three.js。静的書き出しのまま動くこと。3Dのコードは観戦画面を開いたときだけ読み込み、ほかの画面を重くしない。
- **カメラ**：斜め上から見下ろす視点で、ボールを滑らかに追う。ゴール前の場面では少し寄る。PK 戦はキッカーの後ろからゴールを見るなど、PK 戦に合った視点にする。
- **モーション**：演出タイムラインのイベントに合わせて再生する。ボーンは使わず、体の部品を動かすコードのアニメーションでよい。

| 分類 | モーション |
|---|---|
| 基本 | 待機、歩く、走る、方向転換 |
| ボール | パス、ロングキック、シュート、クロス、トラップ、ヘディング（ジャンプ） |
| 守備 | タックル、スライディングタックル、競り合い |
| GK | 構え、セービング（横へ跳ぶ）、キャッチ、パンチング、ゴールキック、飛び出し |
| ドリブルの技 | ダブルタッチ、ルーレット、裏街道、チョップタッチ、シザース（P2b でイベントに記録している `move` を使う。どの技か見て分かる動きにする。技の名前を小さく表示してよい） |

- **スタジアムと演出**（紙吹雪は出さない）
  - ピッチ：芝（刈り込みの縞模様）、ライン、ゴールとネット。
  - 観客席：シルエットの観客。決定機・ゴールで動く。

  - 3D は Three.js をそのまま使う（React Three Fiber は使わない）。作業は 4a（土台と基本の3D観戦）と 4b（動きと演出の仕上げ）に分け、4a で一度マージして実機で重さを確かめる。

  - **CPU校の格の変動（P3 で決定）**：年度替わりの格の上下は、もとの格（学校を作ったときの格）へ戻りやすくする。上下が半々だと 20 年で格が均等に散らばり、全国の格5（S）が年々増えていたため。数値は `src/engine/config/school.ts` の `PRESTIGE_DRIFT`。

## 12. セーブ

- **保存先**：localStorage。容量が足りなくなったらIndexedDBに移行する。
  - 保存の仕組みは抽象化し（ストレージのインターフェースを挟む）、IndexedDBに差し替えやすくする。
- **長期の記録**：OBの記録や歴代の成績は年々増えるので、一定年数より古いものは要約して保存する設計にする（実装はP5）。
- **セーブ枠**：3つ（【未決】で変更可）。
- **オートセーブ**：日付が進むたび、試合が終わるたびに保存する。
- **バージョン管理**：セーブデータにスキーマのバージョンを持たせ、マイグレーション関数を用意する。
  - 公開前の古い形式（架空の県の世界）は読み込まず、「このセーブは古い形式のため読み込めません」と表示する。
- **書き出し・読み込み**：JSON形式でセーブデータを書き出し・読み込みできるようにする（ブラウザのデータ消去への対策）。
- **v6→v7（P4）**：全選手（自校・CPU校・OB）に見た目（17章）を、全学校にユニフォームを付ける。既存のセーブを読み込んだときは乱数で生成して付け、自校のユニフォームはあとで設定画面から変えられることをお知らせで伝える。

| リーグ戦：冬の県予選で負けて3年生が引退した後に、降格した割合 | 報告する（極端に高くないこと） |
| 評判の推移 | 72校（区分ごとに 24校）× 20年で測る。名門 10年前後のまま。測るたびに数ポイント動くので、学校の数は減らさない（balance:full は 30分程度まで） |

- これまでの目標値は、P3 の後もすべて範囲内に収める。

**P4 で足す確認項目**

| 項目 | 目標 |
|---|---|
| 試合エンジンの数値 | 試合エンジンは変えないので、`npm run balance:quick` の数値が P3 と変わらない |
| 3D観戦の動作 | 中くらいの性能のスマホで30fps前後。計測の方法と目標値は `docs/PHASE4_PLAN.md` |
| ほかの画面の読み込み | 3Dのコードを読み込む前の、ほかの画面の読み込みの大きさが増えていない |

- 大量の試合をシミュレーションするテスト（例：1万試合）を `npm run balance` などで実行できるようにする。
- 評判の推移と能力の推移は、ある程度うまい采配をする自動プレイ（チームに合うフォーメーション、試合前に見える情報から相手の型を読んで相性の良い戦術を選ぶ、調子・体力を見た先発選び、疲れた選手の交代、体力を見た練習の選び方）で何年分も進めて測る。

## 15. 設備（P2c）

ゲームにお金（予算）の仕組みはないので、お金を使わずに手に入る形にする。

| 設備 | レベル | 主な効果 |
|---|---|---|
| グラウンド（土 → 人工芝 → ナイター設備付き） | 0〜3 | 練習の効率アップ |
| トレーニングルーム | 0〜3 | フィジカル・走り込みの効率アップ、ケガの予防 |
| ケアルーム（治療・リカバリー） | 0〜3 | 疲労の抜けやすさ、ケガからの復帰が早まる |
| 寮 | 0〜3 | 疲労の抜けやすさ、特待生スカウトでの反応が良くなる |

- **手に入れ方**
  - 評判が上がったときに、学校から整備される（例：中堅になったらグラウンドが人工芝に）。
  - 大会の成績（全国大会出場、地域大会優勝など）。
  - OBからの寄付のイベント（OBの進路がプロなどの場合に起きやすい）。
- **インフレ防止**：練習効率の補正は、スタッフと合わせても上限を設ける（P2a の「全部の効果を合わせて最大+15%程度」の考え方を守る）。
- **評判が下がったとき**：設備のレベルは下げない。
- **CPU校**：評判やランクに応じた簡略化した値で持たせる。
- **画面**：設備の一覧と、次のレベルの手に入れ方のヒントを表示する。
- **グラウンドの段階（P2c で決定。計画 Q15）**：0 土、1 人工芝、2 ナイター設備付き、3 人工芝2面＋ナイター設備。
- **合宿の倍率と上限（P2c で決定。計画 Q11）**：合宿の経験点の倍率は、黄マス・イベントと同じく練習効率の上限（+15%）の外。上限はスタッフと設備の常設の補正にだけかける。
- 段階ごとの効果量と手に入れ方の案は `docs/PHASE2C_PLAN.md` 9章。数値は `src/engine/config/` に置く。

## 17. 見た目とユニフォーム（P4）

### 17.1 選手の見た目

- **体型**：2〜3頭身のデフォルメ（独自の体型。腕と脚は胴体とつながった形）。身長の能力を、頭身や背の高さに少し反映する（長身FWやPK専門GKが見て分かる程度）。フィジカルの能力で体の厚みを少し変えてよい。
- **見た目の要素**（選手ごとに生成して保存する）
  - 髪型（短髪、坊主、長め、ツーブロック、くせ毛など、8種類程度）
  - 髪の色（黒・茶系を中心に数色）
  - 肌の色（数段階）
  - 顔：目・眉・口の形を数種類から組み合わせる
- **表情**：普段の顔に加えて、ゴールした時（笑顔）、失点した時や PK を外した時（悔しい顔）など、場面に応じて変える。
- **背番号**：ユニフォームの背中に表示する。
- **選手の詳細画面**：その選手の見た目（顔か全身）を表示する。
- 新入生・特待生・CPU校の選手も同じ仕組みで見た目を生成する。

### 17.2 ユニフォーム

- **デザインのテンプレート**：7〜8種類程度（例：無地、縦縞、横縞、ハーフ、斜めの帯（サッシュ）、肩・袖の切り替え、胸の太いライン、細いピンストライプ）。
- **色**：メインの色・サブの色に加え、パンツとソックスの色も選べる。
- **1st と 2nd**：学校ごとに2種類を持つ。試合で相手と色がかぶるときは、アウェー側が 2nd を着る。かぶっているかは、メインの色の近さで自動判定する。
- **GK のユニフォーム**：フィールド選手と区別できる別の色（自動で決めてよい）。
- **設定する場所**：学校を作るときにテンプレートと色を選べる（おまかせボタンあり）。あとからメニューでも変えられる（プレビューを見ながら選ぶ画面）。
- **CPU校**：ランダムにテンプレートと色を決める。
- **2D表示**：2D の選手の丸も、ユニフォームのメインの色で塗る。

### 17.3 P4 で決めたこと（2026-10-13。計画 Q3〜Q5・Q7・Q13）

- **背番号**：年度の初めに自動で付け直す（GK の一番手が 1、今のフォーメーションの先発が位置に合わせて 2〜11、攻撃の中心の選手に 10、残りは 12 から学年と総合値の順）。年度の途中は変えない（途中で入る選手は空いている番号）。CPU 校も同じ。2D の丸の番号も背番号にする。
  - 背番号は選手ごとの値として保存する。P5 で手動で変えられる機能を入れる予定（手動で決めた選手は自動の付け直しで飛ばす）。
- **ユニフォームの色**：24 色のパレットから選ぶ（自由な色は選べない）。
- **ホーム・アウェー**：トーナメントは組み合わせ表の上側がホーム、リーグ戦は日程どおり、練習試合は自校がホーム。メインの色の差（CIELAB の色差）が基準値より近ければアウェーが 2nd。それでもかぶればホームが 2nd、さらにかぶればアウェーが予備の無地（白か黒）。
- **GK の色**：両チームのフィールド選手と相手の GK から最も離れた色を、GK 用の色から試合ごとに自動で選ぶ。
- **選手の詳細・ユニフォームの設定・学校作成の絵**：SVG の絵で描く（3D と同じ柄・色・体型。3D のコードは観戦画面だけで読み込む）。
- **髪の色**：黒とこげ茶が中心、茶・赤みの茶・灰みの黒が少し、明るい茶はまれ。金髪などの明るい色は入れない。
- **見た目の要素の持ち方**：種類は設定の一覧の番号で保存し、一覧は後ろに足すだけにする（P5 の留学生で髪の色・肌の色を増やしても、セーブの互換性と今までの選手の見た目が変わらない）。
- 見た目は、ゲームの乱数とは別の系統の乱数（選手の ID とゲームのシードから作る）で生成する。ゲームの結果（新入生の能力など）は変わらない。
