# 頂上イレブン（仮題） 仕様書

> この文書は仕様の正本（Single Source of Truth）です。
> 実装中に仕様と矛盾する判断や、仕様に書かれていない重要な判断が必要になった場合は、勝手に決めずにユーザーに確認し、合意後にこの文書を更新すること。
> 「【未決】」と書かれた項目は、指定フェーズでは仮実装（最小限・差し替えやすい形）にとどめる。

---

## 1. コンセプト

- プレイヤーは高校サッカー部の監督。弱小校を育て、全国の頂点を目指す。
- 中心となる遊び：
  - すごろく式のカレンダー進行（育成・イベント）
  - 3年で部員が入れ替わるサイクル
  - 学校評判が上がるにつれて手札・新入生・スカウト・スタッフ枠が広がる成長ループ
  - 能力に基づく試合シミュレーションと采配
- ゲームに終わりはなく、年度を重ねて学校の歴史が積み上がる。
- 仮タイトルは「**頂上イレブン**」。表示名は `src/engine/config/names.ts` に置き、差し替え可能にする。

## 2. 公開・技術方針

- **収益化**：初期は広告・課金なし。Vercel（Hobby）で無料公開する。人気が出たらアプリ化し、広告・課金を入れる予定。
- **アプリ化への備え**
  - Next.js（App Router）＋TypeScriptで作り、`output: 'export'` による**静的書き出しのみ**で動くこと。API Routes・SSR・Server Actionsは使わない。
  - 将来Capacitor等でアプリ化しやすいよう、ブラウザ標準APIだけで動作させる。
- **デザイン**：スマホ縦画面を最優先。PCでは中央に縦長で表示する。
- **ゲームロジック**：`src/engine/` に**UIから独立した純粋なTypeScript**として実装する。React・DOMには依存しない。
- **乱数**：シード指定できる疑似乱数（PRNG）を使う。乱数の状態はセーブデータに含める。
- **状態管理**：Zustand。
- **テスト**：Vitest。エンジンには単体テストと、大量の試合をシミュレーションするバランステストを必ず用意する。
- **デプロイ**：GitHub → Vercelの自動デプロイ。
- **アクセス解析**：将来の判断材料として、後のフェーズで入れる（Phase 5）。

## 3. 知財・名称ルール（厳守）

- 「パワプロ」「栄冠ナイン」などの名称、それらに固有の用語、キャラクター、UIの見た目を使わない。
  - 避ける用語の例：「進行アイコン」「戦術レベル」「伝令」「転生選手」
- 実在の高校名・選手名・Jクラブ名・大会の正式名称・商標を使わない。
  - 「インターハイ」は商標なので使わない。
- **都道府県名・地域名は実在の名前を使ってよい。** 学校名・選手名・大会の正式名称・商標は、引き続き架空または一般的な名前にする。
  - 実在の高校のデータ（強さ・校数など）は使わない。県ごとの傾向は架空のものにする。
- 大会名などの表示名はすべて `src/engine/config/names.ts` に集約し、後から差し替えられるようにする。
  - 大会の表示名は「**冬の全国大会**」（高校選手権に相当）と「**夏の全国大会**」（インターハイに相当）。
- キャラクターは**独自デザインの2〜3頭身デフォルメ**にする。既存ゲームのキャラクター特有の造形は真似しない。

## 5. すごろく式の進行

- **手札**：評判に応じた枚数の「進行カード」を持つ（6章の表を参照）。カード1枚につき、数字1〜5と種類を持つ。
- **カードの使い方**
  - カードを1枚使うと、その数字の日数だけカレンダーを進む。
  - 使ったカードは補充される（種類と数字はランダム。評判や設備で出やすさが変わる）。
- **1マス＝1日**。1年は4月1日から3月31日までのマスで構成する。
- **カードの種類＝練習の種類**（練習カードの表のうち、そのフェーズで使えるもの。休養を含む）。カードを使うと、その練習を進んだ日数だけ行う。
- **イベントは止まったマスだけ**で発生する。通過したマスでは発生しない。
- **テンポ**：カードを使う操作は1タップで済ませる。移動の演出はスキップできるようにする。
- **経験点**：経験点 ＝ 練習1日あたりの値 × 実際に進んだ日数。
- **必ず止まるマス**：試合・試験・行事などのマスは必ず止まる。その手前で大きな数字のカードを使っても、そのマスで止まる（効果も止まった日数分だけ）。
- **マスの種類**

| マス | 効果 | 実装フェーズ |
|---|---|---|
| 青 | 良いイベント | P1 |
| 赤 | 悪いイベント | P1 |
| 白 | 良いか悪いかランダム | P1 |
| 緑 | 体力回復 | P1 |
| 黄 | 直前の練習の効率アップ | P1 |
| 大マス | 必ず止まる（試合・試験・行事など） | P1 |
| 分岐（☆） | 止まると道を選べる | P2 |
| 人物マス | OB・マネージャーなどのイベント | P2 以降 |

- **練習カード（仮）**：チーム練習として、対象の部員全員に経験点が入る。

| カード | 主に伸びる能力 | 対象 |
|---|---|---|
| シュート練習 | シュート、キック力 | フィールド選手 |
| パス練習 | パス、視野の広さ | 全員 |
| ドリブル練習 | ドリブル、テクニック | フィールド選手 |
| 守備練習 | 守備、判断 | フィールド選手 |
| フィジカル | フィジカル、空中戦 | 全員（空中戦はフィールド選手のみ） |
| 走り込み | スピード、スタミナ | 全員 |
| 戦術ミーティング | 判断、視野の広さ | 全員（判断はフィールド選手のみ） |
| GK練習 | セービング、ハイボール、ポジショニング、キャッチング | GKのみ |
| セットプレー | キック力、空中戦 | フィールド選手 |
| PK練習 | PK駆け引き | 全員（P2） |
| 休養 | 体力を大きく回復 | 全員 |

- **イベント**：P1では10〜15種類の最小限にする（例：差し入れで体力回復、雨で練習中止、ケガ、やる気アップ）。【未決】詳細は後のフェーズで追加する。

## 6. 学校評判

5段階：**弱小 → そこそこ → 中堅 → 強豪 → 名門**（名門が最上位）

| 評判 | 手札の枚数 | 1学年の人数 | うち特待生枠 | スカウトカード（年間） | スカウト範囲 | スタッフ枠 |
|---|---|---|---|---|---|---|
| 弱小 | 4 | 9 | 2 | 2 | 自県 | 1（ヘッドコーチのみ） |
| そこそこ | 5 | 10 | 3 | 3 | 自県 | 1（ヘッドコーチのみ） |
| 中堅 | 6 | 11 | 3 | 4 | 所属地域 | 2（ヘッドコーチ＋1） |
| 強豪 | 7 | 13 | 4 | 5 | 地域＋隣接地域 | 2（ヘッドコーチ＋1） |
| 名門 | 8 | 14 | 5 | 6 | 全国 | 3（ヘッドコーチ＋2） |

- **評判ゲージ**
  - 公式戦と練習試合の勝利で上がる。格上に勝つほど大きく上がる。
  - 負けると下がる。評判が高いほど下がり幅を大きくするが、極端にはしない（不満の原因になりやすいため）。
- **評判の上がる速さの目安**（ある程度うまく采配した場合）：「そこそこ」まで1〜2年、「中堅」まで3〜5年、「名門」まで10年前後。
- **相手校の強さ**：相手校にはランク（E〜S）を付けて表示する。
- **評判とランクは別物**
  - 評判（5段階）は、手札・新入生・スカウトなどを決める学校の格。
  - ランク（E〜S）は、その年のチーム力から計算する強さの目安。自校にも表示する。
  - 目安：弱小≈E、そこそこ≈D、中堅≈C、強豪≈B、名門≈A。**Sは飛び抜けたチームだけ**。

### 7.2 能力項目

**共通（全選手）**

| 項目 | 効果 |
|---|---|
| 身長（cm表示。ランク表示なし） | 空中戦・ハイボールに補正。在学中に少し伸びる。練習では上がらない |
| 視野の広さ | パスの出しどころ（候補）をいくつ見つけられるか。GKの場合は、つなぐかロングボールかの選択に効く |
| キック力 | パスの届く距離、シュートの強さ、FK・CK、ゴールキックの飛距離 |
| スピード | フィールド選手は突破・カウンター・守備への戻り。GKは飛び出しの速さ |
| スタミナ | フィールド選手は疲労の進み方。GKは飛び出しの速さと、試合終盤の質 |
| パス | パスの精度。GKの場合はビルドアップの質 |
| テクニック | トラップ・ボールキープの精度。GKの場合はプレスを受けたときのボール処理 |
| フィジカル | 競り合い、ボールキープ、GKの1対1 |
| PK駆け引き | PKでの読み合い（キッカー・GK両方） |

**フィールド選手専用**

| 項目 | 効果 |
|---|---|
| シュート | シュートの精度、決定率 |
| ドリブル | 1対1の突破 |
| 守備 | タックル、マーク |
| 空中戦 | ヘディングの競り合い |
| 判断 | 守備時・攻撃時のポジショニング、戦術の理解度、パスを出すまでの速さ |

**GK専用**

| 項目 | 効果 |
|---|---|
| セービング | シュートを止める |
| ハイボール | クロスへの対応で、ボールに届くかどうか |
| ポジショニング | 「止めにいける範囲」の広さ |
| キャッチング | ボールを確保できるか。低いと、はじいたボールがこぼれ球になる |

- **内部の持ち方**：内部では全選手が全項目（共通・フィールド専用・GK専用）を持つ。画面には役割（GK／フィールド）に合う項目だけを表示する。役割外の項目は低めで、練習でもほとんど伸びない。

**ランク表示しない属性**
- ポジション適性（GK/CB/SB/DMF/CMF/OMF/WG/CF の各ポジションに◎/○/△）
- 利き足
- 性格（P2）
- 調子、体力、信頼度
- 特殊能力（スキル）：【未決】P2以降に追加

### 7.3 能力どうしの組み合わせ（試合判定で必ず再現すること）

- **視野の広さ × 判断**：見えていても、強い相手には出せない
  1. 視野の広さで、パスの出しどころ（候補）の数が決まる。
  2. 判断で、パスを出すまでの速さが決まる。
  3. 相手の守備の質（守備・判断・プレスの強さ）によって、パスを出せる時間の余裕が短くなる。
  4. 判断の速さがその余裕に間に合わなければ、そのパスは出せない。
  - 結果として、弱い相手には出せるパスが、強い相手には出せなくなる。
- **判断（攻撃時）**：ボールを持っていないときの動き出しの質に効く。良い位置で受けられるかどうかが決まり、チャンスの質が上がる。
- **キック力の組み合わせ**
  - ロングパス＝パス（精度）×キック力（届く距離）。キック力が足りないと、精度が高くても届かずに奪われる。
  - シュート＝シュート（精度）×キック力（強さ）。ミドルシュートはキック力の比重が大きい。
- **GKの判定の流れ**
  1. ポジショニングで「止めにいける範囲」が決まる。
  2. その範囲の中で、セービングで止められるかが決まる。ポジショニングが低いと、セービングが高くても届かないコースが増える。
  3. セーブした後、キャッチングが高ければボールを確保して終わる。低いとこぼれ球になり、相手に2本目のシュートの機会が生まれる。
  4. クロスへの対応は、ハイボールでボールに届くかが決まり、キャッチングで確保できるかが決まる。キャッチングが低いとファンブルが起きる。
- **ビルドアップの戦術とGK**
  - 戦術を「ビルドアップ重視」にすると、GKのパスとテクニックが効く。この2つが低いと、自陣ゴール前でボールを奪われるイベントが起きる。
  - 戦術を「ロングボール主体」にすると、GKのキック力が効く。

### 7.4 成長

- 練習カードの経験点を、該当する能力に振り分ける。
- 能力値が高いほど、次の1ポイントを上げるのに多くの経験点が必要になる（インフレ防止）。
- 選手ごとに隠しパラメーター「伸びしろ」を持たせ、成長量に補正をかける。
- 調整用の数値はすべて `src/engine/config/` に集約する。

## 8. 部員・新入生・特待生スカウト

- **地域区分**（スカウト範囲の「所属地域」「隣接地域」に使う）：北海道／東北／関東／北信越／東海／近畿／中国／四国／九州。

- **部員数**：1学年の人数は評判で決まる（6章の表）。部全体ではおよそ27〜42人。
- **新入生**：4月に入部する。人数は、評判で決まる1学年の人数から、入部が決まった特待生の数を引いた分を一般入部で生成する。
- **特待生スカウト（P2）**
  - 期間は11月〜2月。すごろくにスカウトカードが出る。カードの枚数とスカウト範囲は評判で決まる（6章の表）。
  - **候補の中学生**
    - 所属は「中学の部活」「街クラブ」「Jクラブ系のジュニアユース（架空）」の3種類。
    - 地域ごとに傾向がある（攻撃型が多い、GKが多い、など）。
  - **能力の水準**：特待生の候補は、CPUの強豪校の新入生と同じ水準にする。ただし、取り合いになる最上位の候補は、その一段上にする。
  - **能力表示**：候補リストの能力メーターは正確ではない。中学時代の実績が高い選手ほど表示が正確になる。分析担当スタッフのスカウティング能力が高いほど、メーターと寸評も正確になる。
  - **寸評**：隠れた素質（伸びしろ、性格、適性など）を文章でほのめかす。
  - **反応**：反応は「良好・普通・悪い」の3段階。
    - 能力の高い選手ほど反応が悪くなりやすい。
    - 再訪問すると反応が好転することがある。評判が低いと好転しにくい。
    - 反応が良好でも、入部は確定ではない。
  - **取り合い**：有望な選手ほど、ユースチームや他の強豪校との取り合いになる。
  - **入部**：入部が決まった特待生は、翌年4月に入部する。人数は評判で決まる特待生枠（2〜5人）が上限。
- **卒業**：卒業した部員はOBとして記録する。進路（プロ、大学、社会人、指導者の道など）を持たせる。OBの記録はスタッフ制度で使う。

## 9. スタッフ（コーチ）制度（P2）

- **候補**：スタッフは卒業生（OB）の中から選ぶ。
- **ゲーム開始時**：卒業生がいないため、学校を作るときに架空のOBを数人自動で生成しておく。
- **枠**：評判で決まる（6章の表。名門で最大3人）。
  - **ヘッドコーチは必須**。
  - 残りの枠には、GKコーチ・フィジカルコーチ・分析担当の中から配置する。
- **役割とパラメーター**

| 役割 | 主なパラメーター | 効果 |
|---|---|---|
| ヘッドコーチ（必須） | 指導力、戦術眼 | 練習効率アップ。結果のみモードでの采配の質 |
| GKコーチ | GK指導 | GKの練習効率。PK駆け引きの伸び |
| フィジカルコーチ | 体力管理 | 疲労回復、ケガの予防 |
| 分析担当 | スカウティング | PKの読み、相手の傾向を表示、特待生スカウトの精度 |

- **能力の決まり方**
  - **現役時代の能力**で得意分野が決まる。例：GKだった人はGK指導、判断が高かった人やキャプテン経験者は戦術眼。
  - **卒業後の進路**で伸び方と、スタッフになれる時期が決まる。例：大学に進んだ人は4年後から雇える。プロに進んだ人は引退後に戻ってくる。
  - **「名選手、名監督にあらず」**：指導力は現役時代の強さより、性格や進路で決まる割合を大きくする。
- **成長**
  - 在任中に成長する。成長のきっかけは、在任年数、担当分野の成果、大会成績。
  - **得意分野1〜2個**だけ、上限が100（SS）まで届く可能性がある。それ以外の能力の上限は60〜80程度。
  - 上限の数値は表示しない。寸評でにおわせる。
  - 上限に近づくほど伸びにくくなる。年齢が上がると伸びが止まり、最後は勇退する。
- **インフレ防止**
  - 練習効率の補正は最大でも+15%程度にする。
  - 年齢・在任年数で勇退させる。
  - 優秀なスタッフほど、他校やプロに引き抜かれる確率が上がる。
  - 相手校もスタッフ能力を持つ（簡略化した値でよい）。
- **ヘッドコーチがいなくなった場合**：候補がいなければ、能力の低い「臨時コーチ」を自動で配置する。

## 10. 試合

### 10.1 基本の仕組み

- **結果は確率で決める**：試合エンジンは、確率をもとに「何分に、誰が、何をしたか」というイベントの並びを生成する。物理演算による本格的なシミュレーションはしない。
- **表示は再生するだけ**：テキスト・2D・3Dの各表示は、エンジンが生成したイベントから組み立てた「演出タイムライン」を再生するだけ。表示が試合結果に影響してはならない。
- **区間ごとに計算する**：1区間＝5分として、区間ごとに計算を進める（一度に試合全体を計算しない）。采配を変えると、次の区間から反映される。

### 10.2 試合のルール（大会ごとに設定データで持つ）

| 大会 | 試合時間 | 引き分けの場合 |
|---|---|---|
| 冬の全国大会（準々決勝まで） | 80分 | 延長なしですぐPK戦 |
| 冬の全国大会（準決勝） | 90分 | 延長なしですぐPK戦 |
| 冬の全国大会（決勝） | 90分 | 20分の延長、それでも同点ならPK戦 |
| 夏の全国大会 | 70分 | 決勝のみ延長あり |
| リーグ戦 | 大会設定に従う | 引き分けで終了 |
| 練習試合 | 大会設定に従う | 引き分けで終了 |

- **登録**：試合にエントリーできるのは20人（先発11人＋控え9人）。
- **交代**：最大5人。大会ごとに「交代回数は3回まで」の制限を設定できるようにする。
- 延長戦での追加交代は【未決】。P1ではなしでよい。
- **冬の全国大会の県予選**は、全国大会と同じ試合ルール（上の表）で行う。
- 「交代回数は3回まで」の制限はフラグとしてデータに持つが、P1では使わない。
- **試合中のカード（警告・退場）とケガ**はP2で入れる。P1は疲労のみ。
- **試合中のPK**（ペナルティエリア内のファウル）はP1から発生させる。判定は10.6と同じ。

### 10.3 判定モデル（初期案。数値は調整前提）

1. **ゾーン別の評価値**：選手の能力×ポジション適性×フォーメーション補正から、ゾーンごとの評価値を計算する（攻撃は左・中央・右、中盤、守備は左・中央・右、GK）。
2. **ボール支配**：区間ごとに、両チームの中盤の評価値の比率に戦術補正をかけて支配率を決め、攻撃の回数を確率で配分する。
3. **攻撃1回ごとの判定**
   1. 攻撃ルートを選ぶ（中央／サイド／カウンター／ロングボール／セットプレー）。
   2. 7.3節の「視野の広さ×判断」でチャンスになるかを判定する。
   3. シュートの質を「シュート×キック力」と相手の守備で判定する。
   4. 7.3節のGKの判定の流れで結果を決める（こぼれ球なら2本目のシュートへ）。
4. **疲労**：スタミナとプレスの強度に応じて、区間ごとに体力が減る。体力が下がると能力に補正がかかる。
5. **得点の分布**：変換関数（シグモイド等）で、極端な結果にならないよう調整する。

### 10.4 試合モードと采配

| 試合の種類 | 選べるモード | 采配のタイミング | 表示 |
|---|---|---|---|
| トーナメント（公式の大会） | 観戦のみ（結果のみは選べない） | 試合前・ハーフタイム・観戦中いつでも（一時停止して交代や戦術変更） | 3D（P4。P4までの間はテキスト・2Dで代用） |
| リーグ戦 | 「采配あり」と「結果のみ」を進行中いつでも切り替え可 | 采配ありは試合前とハーフタイムのみ | 采配ありは簡易2D（P3） |
| 練習試合 | リーグ戦と同じ（P1から、試合前に「観戦する／結果のみ」を選べる） | リーグ戦と同じ | リーグ戦と同じ |

- **采配で操作できること**：スタメン、フォーメーション、戦術、交代。
- **フォーメーション（P1）**：4-4-2、4-3-3、4-2-3-1、3-5-2、5-3-2。
- **試合前に見える相手の情報**：基本フォーメーションと攻撃方針だけ。プレス・ラインなどの細かい傾向は、P2で分析担当がいる場合だけ表示する。
- **ハーフタイムに見える情報**：前半の支配率、シュート数（枠内）、ゾーン別（左サイド・中央・右サイド）の攻撃回数と好機の数、どこで押されているか。
- **戦術**

| 項目 | 選択肢 |
|---|---|
| 攻撃方針 | 攻撃的／バランス／守備的 |
| 組み立て | ビルドアップ重視／ロングボール主体 |
| プレス | 高／中／低 |
| ライン | 高／低 |

- **戦術の相性（循環型）**：どの戦術にも苦手な相手がいるようにし、どんな場面でも一番強い戦術は作らない。
  - ハイプレス → つなぐ（ビルドアップ）に強い。ロングボール → ハイプレス（前がかり）に強い。引いて守る（ライン低）→ ロングボールに強い。つなぐ → 引いて守る相手に強い。
  - CPU校は「ポゼッション／ハイプレス／ロングボール／堅守速攻」の4つの型のどれかで戦う。型に合うフォーメーションを使うので、見えている情報（基本フォーメーションと攻撃方針）から型を読める。
- **采配ありを有利にする**：結果のみモードでは、AIの監督が采配する。采配の質はヘッドコーチの戦術眼で決まり、作戦ノートがあればそれも使う。自分で采配した方が有利になるよう調整する。
- **計算は共通**：采配ありでも結果のみでも、同じ試合エンジンで計算する（計算式を分けない）。

### 10.5 作戦ノート（条件付きルール。P2）

- **条件**（いくつでも組み合わせられる）
  - 時間：○分以降、残り○分
  - スコア：○点リード、同点、○点ビハインド
  - 選手の状態：スタミナ○%未満、イエローカード、ケガ
  - その他：交代枠が残っているか、大会の種類
- **行動**
  - 選手交代（A→B）
  - フォーメーション変更
  - 戦術変更
  - ポジション変更
- **優先順位**：ルールに優先順位を付ける。交代枠が足りないときは、優先順位の高いルールから実行する。
- **数の上限**：1つのノートにつき8ルールまで。
- **手動操作が優先**：観戦中に自分で交代したら、関係するルールは止まる。
- **結果のみモード**でも作戦ノートを使う。
- **テンプレート**

| テンプレート | 条件 | 行動 |
|---|---|---|
| パワープレイ | ビハインドで残り10分 | 長身FWを投入し、ロングボール主体に |
| 逃げ切り | 1点リードで残り5分 | 選手Aを投入し、5バックに |
| 疲労交代 | 選手Bのスタミナが5%未満 | 選手Cと交代 |
| PK準備 | トーナメントで同点、残り3分 | PK専門GKを投入 |

### 10.6 PK

- **プレイヤーが決められるのはキッカーの順番だけ**。コースの選択はできない。
- **1本ごとの判定**
  - キッカー側の読み＝キッカーのPK駆け引き＋キッカー側チームの分析担当のスカウティング
  - GK側の読み＝GKのPK駆け引き＋GK側チームの分析担当のスカウティング
  - 相手校も分析担当の能力を持つ。
  - キッカーがGKの逆を突いた場合：ほぼ得点になる。ただし、キック精度が低いと枠を外すことがある。
  - GKが読みを当てた場合：「シュート＋キック力」と「セービング＋ポジショニング」を比べて結果を決める。
- **ルール**：5本ずつ蹴り、決着しなければサドンデス。PK戦に参加できるのは、試合終了時にピッチにいた選手のみ（だからPK専門GKは試合終盤に投入する）。
- 試合中のPKも同じ判定を使う。
- P1ではスタッフがいないので、スカウティングの項は0として扱う。

### 10.7 観戦の時間

- **等速**：試合時間15分＝現実の1分。80分の試合で約5分20秒、ハーフタイムとPK戦を含めて1試合6〜8分が目安。
- **倍速**：2倍と4倍を選べる。
- **テキスト表示（P1）**：テキスト速報、スコアボード、試合の流れ（モメンタム）の表示。
- **試合中のセーブ**：区間（5分）ごとに試合の状態と乱数の状態をセーブし、リロードしたらその区間から再開する（やり直しで結果を変えられない）。

## 11. 大会

- **冬の全国大会（P1）**
  - 都道府県は実在の47都道府県。学校を作るときに、自県を47都道府県から選ぶ。
  - 県予選：自県の16〜32校によるトーナメント。参加校数と強さの分布は、県ごとの区分（激戦区／普通／少数）で変わる。区分は架空の傾向として設定データで持つ。
  - 全国大会：48校のトーナメント（各都道府県から1校、東京のみ2校）。東京の予選は、代表決定戦（準決勝にあたる試合）の勝者2校が代表になる。
- **学校の持ち方（セーブ容量の都合）**
  - 自県は、全校が部員を持つ。
  - 他県は、県ごとに数校（区分で変わる）だけが部員を持つ。毎年その中から、同じ試合エンジンで代表を決める（表示しない）。
  - 学校名（自校以外）は架空の名前で生成する。
  - CPU校の部員は、圧縮した形式で保存する。
- **練習試合**：年に6〜8回、すごろくの大マスとして出る。
  - 相手は自県の学校。基本は自校とランクが近い（±1）学校。2〜3回に1回は、ランクが1〜2段階上の学校とも組まれる。
  - 70分、同点で終了、交代5人。
- **夏の全国大会・新人戦（P2）**
- **リーグ戦（P3）**：県リーグから始める。上位リーグ（地域リーグ、全国リーグ）と昇格・降格はP5。
- **相手校**：相手校もCPUの学校として部員を毎年入れ替えて成長させる（簡略化したモデルでよい）。
  - 試合のときは、CPU校の部員にも体力・調子・欠場者の変動を付ける（自校がすごろくで抱える疲労などと条件をそろえる）。値は保存しない。

## 12. セーブ

- **保存先**：localStorage。容量が足りなくなったらIndexedDBに移行する。
  - 保存の仕組みは抽象化し（ストレージのインターフェースを挟む）、IndexedDBに差し替えやすくする。
- **長期の記録**：OBの記録や歴代の成績は年々増えるので、一定年数より古いものは要約して保存する設計にする（実装はP5）。
- **セーブ枠**：3つ（【未決】で変更可）。
- **オートセーブ**：日付が進むたび、試合が終わるたびに保存する。
- **バージョン管理**：セーブデータにスキーマのバージョンを持たせ、マイグレーション関数を用意する。
  - 公開前の古い形式（架空の県の世界）は読み込まず、「このセーブは古い形式のため読み込めません」と表示する。
- **書き出し・読み込み**：JSON形式でセーブデータを書き出し・読み込みできるようにする（ブラウザのデータ消去への対策）。

## 14. バランスの目標値（初期。テストで検証する）

| 項目 | 目標 |
|---|---|
| 1試合の総得点（平均） | 2.5〜3.5 |
| トーナメントでPK戦になる割合 | 15〜25% |
| 同格（同じランク）の相手への勝率 | 40〜50%（残りは引き分けと負け） |
| ランクが2段階上の相手への勝率 | 15〜25% |
| 能力の推移 | 一般入部の選手が、卒業時に総合B以上に届く割合が5〜8%（P2のスタッフ補正が加わる前） |
| 評判の推移 | ある程度うまい采配で、「そこそこ」まで1〜2年、「中堅」まで3〜5年、「名門」まで10年前後 |
| 采配の効果 | ある程度うまい采配の自動プレイで、同じランクの相手への勝率50〜55% |
| 戦術の相性 | どの型にも苦手な相手がいる（相性表で確認する） |

- 大量の試合をシミュレーションするテスト（例：1万試合）を `npm run balance` などで実行できるようにする。
- 評判の推移と能力の推移は、ある程度うまい采配をする自動プレイ（チームに合うフォーメーション、試合前に見える情報から相手の型を読んで相性の良い戦術を選ぶ、調子・体力を見た先発選び、疲れた選手の交代、体力を見た練習の選び方）で何年分も進めて測る。
