### 1.5 作戦ノート（新規 `src/engine/types/note.ts`）

```ts
/** 選手の指定。特定の選手か、試合中に条件で選ぶか */
export type PlayerRef =
  | { kind: "player"; id: string }
  | { kind: "auto"; pick: AutoPick };
export type AutoPick =
  | "lowestStamina"     // ピッチ上でスタミナが最も低いフィールド選手
  | "bestForSlot"       // 下げる選手の位置に最も合う控え
  | "tallestForward"    // 控えで最も背の高い FW 適性の選手（パワープレイ用）
  | "pkGoalkeeper"      // 控えの GK で PK 駆け引きが最も高い選手（PK 準備用）
  | "goalkeeperOnPitch" // ピッチ上の GK
  | "bookedPlayer"      // イエローカードを受けている選手
  | "injuredPlayer";    // ケガをした選手

export type NoteCondition =
  | { type: "minuteFrom"; minute: number }                       // ○分以降
  | { type: "minutesLeft"; minutes: number }                     // 残り○分（5 章の定義を参照）
  | { type: "score"; state: "lead" | "draw" | "behind"; by?: number } // ○点リード（以上）、同点、○点ビハインド（以上）
  | { type: "stamina"; target: PlayerRef; below: number }        // スタミナ○%未満
  | { type: "booked"; target: PlayerRef }                        // イエローを受けている
  | { type: "injured"; target: PlayerRef }                       // ケガ
  | { type: "subsLeft"; atLeast: number }                        // 交代枠が○人以上残っている
  | { type: "competition"; kinds: ("practice" | "prefQualifier" | "national")[] }; // 大会の種類

export type NoteAction =
  | { type: "sub"; out: PlayerRef; in: PlayerRef }
  | { type: "formation"; formation: FormationId }
  | { type: "tactics"; change: Partial<Tactics> }          // 変えたい項目だけ
  | { type: "position"; player: PlayerRef; slot: number };  // フォーメーションの○番目の枠へ（元の枠の選手と入れ替え）

export interface NoteRule {
  id: string;
  name: string;            // 例：「パワープレイ」。速報に出す
  enabled: boolean;
  conditions: NoteCondition[]; // すべて満たしたとき（AND）
  actions: NoteAction[];       // 上から順に実行
}

export interface TacticsNote {
  id: string;
  name: string;
  rules: NoteRule[]; // 並び順が優先順位。最大 8
}
```

- `GameState.notes: TacticsNote[]`（最大 3 冊）と `GameState.selectedNoteId?: string`（前回選んだノート）。

## 2. スタッフの能力の決まり方（初期案）

### 2.1 現役時代から「素地」を出す（0〜1）

| 能力 | 素地の計算 |
|---|---|
| 戦術眼 | (判断 × 0.6 ＋ 視野 × 0.4) / 100。主将なら ＋0.1。GK は (視野 ＋ ポジショニング) / 200 × 0.8 |
| GK指導 | GK：(セービング ＋ ハイボール ＋ ポジショニング ＋ キャッチング) / 400。フィールド選手：0.15 |
| 体力管理 | (スタミナ ＋ フィジカル) / 200 |
| スカウティング | (視野 × 0.4 ＋ 判断 × 0.3 ＋ PK駆け引き × 0.3) / 100 |
| 指導力 | **総合 / 100 × 0.2 ＋ 指導の素質 × 0.8**（名選手、名監督にあらず。素質は Phase 2b で性格に置き換える） |

- 指導の素質は、卒業時に正規分布（平均 0.5、標準偏差 0.18）で決めます。現役の強さとは無関係です。

### 2.2 進路（卒業時に決まる。Phase 1 の 5 種類をそのまま使う）

| 進路 | 雇える時期 | 雇えるときの能力の補正 | 伸び方 |
|---|---|---|---|
| プロ入り | 引退後（卒業の 8〜14 年後、26〜32 歳） | 戦術眼・GK指導・体力管理 ＋8 | ×0.9（完成済みで伸びは控えめ） |
| 大学進学 | 卒業の 4 年後（22 歳） | なし | ×1.0 |
| 社会人チーム | 引退後（卒業の 6〜10 年後） | 体力管理 ＋5 | ×0.95 |
| 指導者の道 | 卒業の 4 年後（資格を取ってから） | 指導力 ＋10、戦術眼 ＋5 | ×1.2（一番伸びる） |
| その他の進路 | 卒業の 4〜10 年後 | すべて −5 | ×0.9 |

- 指導者の道を選ぶ割合（Phase 1 は重み 8）を少し上げ、毎年 1〜2 人は候補が増えるようにします。

### 2.3 雇えるときの能力と上限

- 雇えるときの能力 ＝ 15 ＋ 45 × 素地 ＋ 進路の補正 ＋ 誤差（標準偏差 5）。範囲は 5〜70。
  - だいたい F〜E（20〜49）。素地が飛び抜けていれば D。最初から強いスタッフはいません。
- **得意分野**：素地が最も高い能力。2 番目との差が 0.08 以内なら、2 つとも得意分野にします（1〜2 個）。
- **上限（隠し）**
  - 得意分野：78 ＋ 22 × 素地 ＋ 誤差（標準偏差 6）。範囲は 75〜100。素地が高いほど 100（SS）に届きやすくなります。
  - それ以外：60〜80 の一様乱数。ただし、雇えるときの能力 ＋5 は下回らないようにします。
- **寸評**（上限は出さず、においを出す）
  - 「上限 − 現在」が大きい：「この分野はまだ伸びしろがありそうだ」
  - ほぼ上限：「この分野はもう完成の域に近い」
  - 得意分野：「〇〇については天性のものを感じる」（指導力なら「教え方がうまいと評判だ」など、能力ごとに文言を変える）

### 2.4 架空の OB（ゲーム開始時とマイグレーション）

- 5〜6 人を生成します。卒業年は過去（年齢 24〜50 歳）、全員がすぐ雇える状態です。
- 進路はばらけさせ、少なくとも 1 人は「指導者の道」、1 人は GK 出身にします（ヘッドコーチと GK コーチを選べるように）。
- 能力は 2.3 と同じ式で作ります。最初から D を超える人は出さず、強いスタッフは自分の OB から育てる流れにします。

## 3. スタッフの成長の式（初期案）

年度末（3 月の卒業式の後）に、在任中のスタッフ全員について計算します。

```
伸び(能力k) = 基本値 6 × 役割の重み(k) × 進路の倍率 × 年齢の倍率 × 伸びしろ(k) × (1 ＋ 成果ボーナス) ＋ 誤差
伸びしろ(k) = clamp((上限k − 現在k) / 30, 0, 1)     … 上限に近いほど伸びにくい
年齢の倍率   = 45 歳まで 1.0、そこから 60 歳で 0 になるよう直線で下がる
役割の重み   = 役割の主な能力 1.0（ヘッドコーチは指導力と戦術眼の両方）、それ以外 0.25
```

- **在任年数**：毎年この式で伸びるので、長く任せるほど伸びます。
- **成果ボーナス**（0〜0.5）

| 役割 | 成果 |
|---|---|
| ヘッドコーチ | 大会成績（県予選の勝ち上がり、全国大会の勝利数、優勝） |
| GKコーチ | 担当 GK の能力の伸びと、公式戦 1 試合あたりの失点の少なさ |
| フィジカルコーチ | 部員のケガの日数の少なさ（基準値との比較） |
| 分析担当 | PK 戦の勝ち、試合中の PK の成功・阻止 |

- 目安：得意分野で素地の高い人が「指導者の道」から来た場合、35 → 70 前後まで 8〜10 年。100 に届くのは、条件がそろった一部の人だけです。
- **勇退**：60 歳から毎年 20% の確率で勇退。68 歳で必ず勇退します。勇退は年度末に告知します。
- **引き抜き**
  - 毎年 12 月 1 日に判定します。確率 ＝ 0.25 × clamp((最も高い能力 − 65) / 30, 0, 1)^1.5（能力 95 で年 25%、80 で年 9% 程度）。
  - 当たったら予告のイベントを出します（「○○コーチに他校から誘いが来ているらしい」。能力 90 以上ならプロからの誘いもある）。
  - 年度末に 70% の確率で去り、30% は残ります（確認したいこと 4）。

## 4. スタッフの効果（初期案）

| 役割 | 効果 | 式（初期値） |
|---|---|---|
| ヘッドコーチ | 全体の練習効率 | ＋(指導力 − 20) / 80 × 10%（指導力 20 以下は 0） |
| ヘッドコーチ | 結果のみモードの采配の質 | AI の質 ＝ 戦術眼 / 100（5 章） |
| GKコーチ | GK の練習効率（GK 練習・PK 練習） | ＋(GK指導 − 20) / 80 × 10% |
| GKコーチ | GK の PK 駆け引きの伸び | PK 練習の GK への経験点 ＋(GK指導 − 20) / 80 × 15%（上の補正と合わせて 15% まで） |
| フィジカルコーチ | 疲労回復 | 毎日の自然回復 ＋(体力管理 / 100) × 30% |
| フィジカルコーチ | ケガの予防 | 練習中・試合中のケガの確率 −(体力管理 / 100) × 40% |
| 分析担当 | PK の読み | 読み ＝ PK駆け引き ＋ スカウティング × 0.25（balance で調整） |
| 分析担当 | 相手の細かい傾向 | 試合前の画面に、相手のプレスとラインを表示する |

- **balance で調整した値（2026-10-09）**：ヘッドコーチの練習効率 10% → 7%、フィジカルコーチの回復 30% → 15%、PK のスカウティング係数 0.25 → 0.04（`src/engine/config/staff.ts` が正）。
- **練習効率の合計の上限は ＋15%**（`STAFF_EFFECTS.practiceCap`）。1 人の選手にかかる補正をすべて足して、15% で切ります。
- 臨時コーチ：全能力 15〜25。練習効率の補正はほぼ 0 です。
- CPU 校：戦術眼は AI の采配の質に、スカウティングは PK の読みに使います。

## 5. 試合中のカード・ケガと作戦ノートのエンジン

### 5.1 ファウル・カード

- **ファウル**：守備の判定（ドリブル突破・カウンター・ボックス内のチャンスなど）のたびに、確率で起きます。確率は守備側の守備・判断が低いほど、プレスが高いほど、攻撃側のドリブル・スピードが高いほど上がります。
- **場所**：ボックス内なら PK、ボックス外ならフリーキック（既存のセットプレー）です。Phase 1 の「ボックス内のチャンスで一定確率の PK」は、このファウルの流れに置き換えます。
- **カード**：ファウルの一部がイエロー、まれに一発レッド。2 枚目のイエローで退場です。
- **目安**：ファウルは両チーム合計で 1 試合 12〜16 回（速報に出すのはカードと PK・FK につながったものだけ）。イエロー 2〜3 枚、レッドは 30〜40 試合に 1 枚。
- **退場者が出たら**
  - その枠を空きにします（`emptySlots`）。10 人用のフォーメーションは追加しません。
  - 人数差の補正（`MATCH.manDown`）：支配率 −0.05、守備の質 −4、攻撃回数 ×0.9、残りの選手の疲労 ＋10%（1 人あたり）。
  - GK が退場したら、控えに GK がいて交代枠が残っていれば、フィールド選手 1 人を下げて GK を入れます（自動）。いなければ、フィールド選手が GK をします。
- **出場停止**：一発レッドでも 2 枚目のイエローでも、次の公式戦 1 試合は出場停止です。練習試合には出られます。

### 5.2 試合中のケガ

- 区間ごとに、ピッチ上の各選手に確率でケガが起きます。スタミナが低いほど、ファウルを受けたほど上がります。フィジカルコーチの体力管理で下がります。
- **目安**：両チーム合計で 8〜10 試合に 1 件。
- ケガをした選手はすぐにピッチを離れ、その区間の残りは 10 人で戦います。次の区間の頭で交代します（通常の枠を使う）。
  - 観戦中：自動で一時停止して、代わりの選手を選んでもらいます（作戦ノートに「ケガ」のルールがあれば、それが先に動きます）。
  - 交代枠が残っていなければ、人数が減ったまま戦います。
- 重さ（軽い 3〜7 日／中くらい 8〜20 日／重い 21〜45 日）に応じて、試合後に離脱日数（`injuryDays`）を付けます。

### 5.3 作戦ノートの判定

- 判定のタイミング：区間の終わり（CPU の AI と同じ）。発動した行動は次の区間の頭で反映されます。
- **「残り○分」の定義**：「今のスコアのまま進んだら、試合が終わる（または PK 戦に入る）までの時間」。
  - 延長がある決勝で同点なら、延長の終わりまでを数えます。そのため「PK 準備」は延長の終盤に発動します。
  - 決勝でもリードや負けている場合は、90 分の終わりまでを数えます。
- **1 試合 1 回**：ルールは、一度発動したらその試合では終わりです。
- **優先順位**：上のルールから判定します。1 つのルールの行動は、全部実行できるときだけ発動します（交代枠が足りなければそのルールは見送り、下のルールに進みます）。
- **手動操作で止まるルール**

| 自分でしたこと | 止まるルール |
|---|---|
| 交代（A→B） | A か B を指定しているルール（行動・条件のどちらでも） |
| フォーメーション変更 | フォーメーション変更か、ポジション変更を含むルール |
| 戦術変更 | 戦術変更を含むルール |
| ポジション変更 | ポジション変更を含むルール |

- 止まったルールは観戦画面に「停止中」と出します。
- **結果のみモード**（練習試合）：ノートを先に判定し、ノートが決めていない部分（交代・戦術）を AI が判断します。AI の質はヘッドコーチの戦術眼で決まります。
  - 質が高いほど：疲れた選手を適切な時間に代える、ハーフタイムに相手の型を見て相性の良い戦術に変える、リード・ビハインドに応じて方針を変える。
  - 質が低いほど：交代が遅れる・しない、戦術を変えない、まれにちぐはぐな変更をする。
  - 戦術眼 100 でも、Phase 1 の「うまい采配の自動プレイ」と同じくらいまでにします（自分で采配した方が有利という原則を守る）。
- CPU 校の AI も、同じ仕組みで戦術眼に応じた質で動きます。

### 5.4 テンプレート（SPEC 10.5 の表のとおり）

| テンプレート | 条件 | 行動 |
|---|---|---|
| パワープレイ | 1 点以上ビハインド、残り 10 分 | 控えで最も背の高い FW を投入（最もスタミナの低いフィールド選手と交代）、ロングボール主体・攻撃的に |
| 逃げ切り | 1 点リード、残り 5 分 | 選手 A（初期値は「下げる選手の位置に最も合う控え」）を投入、5-3-2 に |
| 疲労交代 | 選手 B のスタミナが ○%未満 | 選手 C と交代（初期値は B＝最もスタミナの低い選手、C＝その位置に最も合う控え） |
| PK 準備 | 公式戦、同点、残り 3 分 | 控えの GK のうち PK 駆け引きが最も高い選手を、今の GK と交代 |

- 疲労交代のしきい値は確認したいこと 5 を参照。

```

├──────────────────────────┤
│ もし（すべて満たしたら）            │
│ ┌ [残り] [−] 10 [＋] 分 ────── ✕┐│
```

- 条件・行動の追加は、下から出るシート（種類の一覧）から選びます。

## 8. PK のスカウティングと PK 練習

- `resolvePkKick` の `kickerScouting`／`gkScouting` に、各チームの `scouting × 0.25` を渡します（自校は分析担当、CPU 校は `cpuStaff`、いなければ 0）。試合中の PK も同じです。
- PK 戦に参加できるのは試合終了時にピッチにいた選手だけです（Phase 1 から。退場者は除く）。「PK 準備」で投入した GK が蹴る側・守る側の両方に入ることをテストで確かめます。
- **PK 練習**：対象は全員、伸びるのは PK 駆け引き（1 日 3.0）、体力 −3。出やすさは他の練習の半分くらいにします。GK コーチがいると、GK の伸びに 4 章の補正がかかります。

## 9. セーブデータ（スキーマ v2 → v3）

`SCHEMA_VERSION` を 3 に上げ、`MIGRATIONS[2]` を追加します。

| 対象 | 変換の内容 |
|---|---|
| ゲーム全体 | `staff`（空。臨時コーチを配置）、`notes: []` を足す |
| OB | 架空の OB を 5〜6 人追加する。既存の OB には `wasCaptain`（その年の卒業生で総合が最も高い人を主将とみなす）、`record`（記録なし）、`staffProfile`（現役最後の能力から 2 章の式で作る）を足す |
| 部員（圧縮形式） | 末尾に `suspended`、`record` の欄を足す（無ければ 0） |
| CPU 校 | `cpuStaff` を格から作る |
| 手札 | 変更なし（PK 練習は新しく引いたカードから出る） |
| 進行中の試合 | 新しい欄（カード・空き枠・スカウティング・AI の質）を初期値で埋める |

- 乱数は、ゲームの seed から作った専用の乱数（`fork("migrate-v3")`）を使います。同じセーブからは、毎回同じ OB が生まれます。
- マイグレーションの後、ヘッドコーチは臨時コーチになっています。欠員と同じ扱いなので、年度の途中でもすぐ OB から選べます（「ヘッドコーチを選べます」と知らせを出す）。
- テスト：Phase 1 の形式（v2）のセーブを fixture として保存し、読み込み→OB の追加→そのまま 1 年進められることを確かめます。

## 12. 確認したいこと

それぞれ「提案」のとおりでよければ、そのまま進めます。

1. **主将**：Phase 1 には主将がいません。戦術眼の素地に使うため、**提案**：毎年 4 月に 3 年生から自動で決めます（総合と判断が最も高い選手）。部員の一覧に印を付け、OB の記録に残します。自分で選べるようにするのは Phase 2b（性格と合わせて）。
2. **年度途中の解任**：**提案**：解任はいつでもできます。空いた枠は欠員なので、年度の途中でも補充できます。ただし、解任した人はその年度は雇い直せません。（解任と補充で、実質的に年度の途中でも入れ替えられることになります。年度の途中は「補充できるのはヘッドコーチだけ」のように絞ることもできます）
3. **年度の途中で評判が上がり、枠が増えたとき**：**提案**：増えた枠は欠員とみなし、すぐ補充できます。（枠が減ったときは、指示どおり次の年度初めに誰を残すか選びます）
4. **引き抜きの予告のあと**：**提案**：12 月に予告し、年度末に 70% の確率で去ります。Phase 2a では引き留める手段は作りません。
5. **「疲労交代」のしきい値**：SPEC の表は「スタミナ 5% 未満」ですが、今の試合エンジンでは、交代なしで 90 分走ったときの体力は中央値で 56%、低い選手でも 25% 程度までしか下がらないため、5% では発動しません（200 試合で計測）。**提案**：テンプレートの初期値を「60% 未満」にします（ノートで変えられる）。SPEC の表も直します。
6. **観戦中のケガの交代**：**提案**：自動で一時停止して、代わりの選手を選んでもらいます。選ばずに再開したら、その位置に最も合う控えを自動で入れます。
7. **CPU 校の選手のケガ・退場**：**提案**：その試合の中だけ反映し、離脱日数や出場停止は持ち越しません（CPU 校には Phase 1 から試合ごとの欠場者の変動があり、それで代わりにします）。自校の選手だけ持ち越します。
8. **退場で 10 人になったとき**：**提案**：10 人用のフォーメーションは足さず、空いた枠のまま人数差の補正をかけます。プレイヤーは既存のフォーメーションに変えることはできます。
9. **「残り○分」の数え方**：5.3 のとおり、「今のスコアのままなら試合（または PK 戦の前）が終わるまでの時間」でよいか。
10. **ルールの発動**：5.3 のとおり、「1 試合 1 回」「行動を全部実行できるときだけ発動」でよいか。
11. **分析担当の傾向の表示**：**提案**：分析担当がいれば、相手のプレスとラインを正確に表示します。スカウティングの能力で表示の正確さを変えるのは、特待生スカウトと合わせて Phase 2b にします。
12. **結果のみモードの采配の上限**：**提案**：戦術眼 100 のヘッドコーチでも、Phase 1 の「うまい采配の自動プレイ」と同じくらいまでにします。
13. **スタッフの年齢と勇退**：**提案**：60 歳から毎年 20% の確率で勇退し、68 歳で必ず勇退します。年齢は卒業時を 18 歳として、年度ごとに 1 つ上がります。
