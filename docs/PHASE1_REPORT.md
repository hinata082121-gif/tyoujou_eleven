# Phase 1 実装報告

## 1. 実装した内容

### ゲームの流れ
タイトル → セーブ枠 3 つ → 学校作成 → すごろくで 1 年 → 冬の選手権（県予選 → 全国大会 32 校）→ 敗退（または優勝）で 3 年生が引退 → 卒業式（OB として進路付きで記録）→ 年度末 → 4 月に新入生、を繰り返す。
エンジンだけで 3 年間を自動で回すテスト（`src/engine/game/game.test.ts`）と、ブラウザ（幅 375px）での画面確認で、途切れずに続くことを確認した。

### エンジン（`src/engine/`。React・ブラウザ API に依存しない）
| 部分 | 内容 |
|---|---|
| `rng` | シード付き PRNG（sfc32）。状態は `number[4]` でセーブに含める |
| `config/` | バランスの数値はすべてここ。表示名は `names.ts` |
| `player` | 能力 17 項目・ランク SS〜G・身長（cm）・利き足・適性 ◎○△・伸びしろ（隠し）・成長（能力が高いほど必要経験点が増える） |
| `school` | 自県 16〜32 校（全校が部員を持つ）、他県 31 県 × 3 校、CPU 校の年次更新、チーム力 → ランク E〜S |
| `calendar` / `practice` / `events` | 1 マス = 1 日の 365 マス、手札（評判で枚数）、カード = 練習の種類 × 数字 1〜5、必ず止まる大マス、青・赤・白・緑・黄、イベント 14 種、体力・調子・ケガ（簡易） |
| `match` | 5 分ごとの区間計算、ゾーン評価・支配率・攻撃ルート（中央／サイド／カウンター／ロングボール／セットプレー）、視野×判断、キック力の組み合わせ、GK のポジショニング → セービング → キャッチング（こぼれ球）、ビルドアップとプレス、疲労、モメンタム、試合中の PK、PK 戦、CPU の采配 |
| `competition` | トーナメント表（シード・不戦勝）、CPU 同士の試合は同じエンジンで計算 |
| `reputation` | 5 段階 + ゲージ。格上に勝つほど上がり、負けると下がる（評判が高いほど下がり幅が大きい） |
| `season` / `game` | 引退・卒業・進路・年度替わり、ゲーム全体の進行（UI はここだけを呼ぶ） |

### セーブ（`src/lib/save/`）
- 保存先はインターフェース（`StorageAdapter`）で抽象化。今は localStorage、IndexedDB に差し替え可能。
- スキーマのバージョン + マイグレーション関数（`migrations.ts`）。
- 部員を配列に詰めた圧縮形式 + LZ 圧縮。CPU 校（容量の大部分）は別キーにして、変わったときだけ書き込む（通常の 1 回の保存は 30ms 程度）。
- 日付が進むたび・試合の 5 分ごと・試合終了でオートセーブ。JSON の書き出し・読み込みあり。

### 画面（テキスト版。スマホ縦 360〜430px 優先）
すごろく（1 タップでカード使用、移動演出はスキップ可）、部員一覧（並べ替え・ポジションで絞り込み）、選手詳細、トーナメント表、記録（歴代成績・OB・出来事）、メニュー、試合前（スタメン 11・控え 9・フォーメーション・戦術）、観戦（テキスト速報・スコア・試合の流れ・等速／2 倍／4 倍・一時停止して采配）、ハーフタイム、PK 戦（キッカー順のみ、1 本ずつ演出）、試合結果、卒業式、年度末、新入生。

| 対戦 | 勝 | 分 | 負 | PK戦の勝率 |
|---|---|---|---|---|

| 1段階上 | 29.6% | 17.3% | 53.1% | 47.8% |

- 1 試合のシュート 15.8 本・枠内 8.7 本・決定率 21%、試合中の PK は 1 試合あたり 0.14 本。
- 2 段階上の相手に PK 戦の勝ちも含めて「勝ち上がる」割合は 26.7%。強い方が有利だが、運でひっくり返ることもある手触りになっている。
- 成長（一般入部 → 3 年間、単純な方針で練習）：総合値の平均 35.9（F）→ 60.7（C）。総合 B 以上は 3.0%、主要能力のどれかが B 以上は 43.5%、A 以上は 2.3%。

### 調整した数値（`src/engine/config/match.ts` ほか）
| 数値 | 初期 → 調整後 | 理由 |
|---|---|---|
| `skillCompression`（新設） | 1.0 → 0.5 | 判定の各段階で能力差が積み重なり、2 段階上への勝率が 3% しかなかった |
| `matchDayFormSd`（新設） | 0 → 0.1 | その日の出来のぶれ。番狂わせを増やし、同格の引き分けを減らす |
| `attacksPerSegment` | 2.7 → 2.25 | 平均得点が 4 点を超えていた |
| `possessionExponent` | 2.2 → 1.6 | 中盤の差が支配率に効きすぎていた |
| `momentumPossession` | 0.0005 → 0.002 | 流れの影響を少し強めて、得点の偏り（引き分けの減少）を作る |
| `onTargetBias` | 50 → 61 | 枠内率が 70% と高すぎた |
| `pkFoulChance` | 0.022 → 0.012 | 試合中の PK が 1 試合 0.37 本と多すぎた |
| `ai.subFitnessBelow` | 52 → 76 | CPU がほとんど交代しなかった |
| 学校の格ごとの新入生の基準値・ランクの境界 | — | 格ごとのチーム力が等間隔（約 4）になるように合わせた |
| 伸びしろの分布 | sd 0.17 → 0.2 | 一般入部から B に届く選手をまれに出す |

## 3. 仕様からずれた点・仮実装にした点
1. **試合判定の「変換関数」**（SPEC 10.3-5）は、能力差の圧縮（`skillCompression`）と、その日の出来（チームごとに ±10% 程度）として実装した。判定式そのものは 7.3 の流れのまま。
2. **ランクの境界**：ベスト 11 の評価値の平均で D≥50・C≥54・B≥58・A≥62・S≥66.5。自県の学校は E〜C が中心で、S は約 3%（他県の上位校を含めた全体では約 7%）。
3. **CPU 校の成長**：簡略化モデル（全能力に毎年一定の経験点）を 4 月と 10 月 1 日に半分ずつ入れる。プレイヤー校の練習による成長と同じくらいの伸びになるよう合わせた。
4. **評判ゲージの増減**：勝利 = 基本値（練習試合 3／県予選 5／全国 9）× ランク差の倍率、敗戦 = 基本値 × ランク差の倍率 × 評判の倍率（0.8〜1.4）、PK 負けは 0.7 倍。県予選優勝 +18、全国大会の勝利ごと +4、全国優勝 +40。いずれも仮の値。
5. **日程**：県予選は 9/14〜11/9 の 4〜5 ラウンド、全国大会は 12/29・12/31・1/3・1/10・1/12。練習試合は 12 月・1 月・3 月を除く月に 1〜2 回。
6. **イベント**：14 種（良い 7・悪い 5・白マス専用 2）。文言と数値は仮。
7. **進路**：総合値による重み付きの抽選（プロ・大学・社会人・指導者・その他）。OB には現役最後の能力を残す（P2 のスタッフ制度用）。
8. **試合後の疲労**：出場した選手は試合後に体力が減る（試合中の消耗に比例）。
9. **PK 戦**：11 人全員が蹴り終わっても決着しなければ、同じ順番でもう一巡する。
10. **ログ**：「出来事」は直近 300 件だけ保存。歴代成績と OB は全件保存（古い記録の要約は P5）。
11. **練習試合**：観戦のみ（P1 では「結果のみ」なし）。
12. **試合中のリロード**：最後に計算した 5 分の頭から再生し直す（結果は同じ）。

## 4. Phase 2 に進む前に判断してほしいこと
1. **試合の運の大きさ**：同格 40% 勝ち・2 段階上に 20% 勝ち（PK 戦込みで 27% 勝ち上がり）で良いか。もっと実力どおりにしたい場合は `skillCompression` を上げる。
2. **評判の上がる速さ**：単純な自動プレイでは、「そこそこ」に上がるのが 4〜5 年目（5 年で上がらない場合もある）。もっと早く（または遅く）したいか。
3. **1 年の長さ**：カード操作が 1 年で約 125 回、試合は 1 年で 15 試合前後（練習試合 13〜15 + 選手権。等速なら 1 試合 5〜7 分、4 倍速で 1.5 分程度）。練習試合が多すぎると感じる場合は、月 1〜2 回を減らすか、P3 の「結果のみ」を練習試合だけ先に入れるか。
4. **成長の速さ**：一般入部で総合 B に届くのは 3% 程度。もう少し多くしたいか（特待生が入る P2 で全体の水準が上がる点も考慮）。
5. **仮の表示名**：県名・学校名・大会名（「冬の選手権」）は仮。差し替えたい名前があれば `names.ts` を変える。
6. **P2 の特待生・スタッフの水準**：CPU の強豪校は「格」の高い新入生（特待生相当）で強さを保っている。P2 で自校に特待生が入ったときに、これと同じくらいの水準にするか。
